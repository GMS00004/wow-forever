# PregaoForever Auction Addon Design — Forever Auction Facts, a Design Gate & a Third-Party AGENTS.md Notice

> Foto de 2026-11-26 de uma página do second brain do Bruno (criada em 2026-11-16, atualizada em 2026-11-16), em inglês. Não é atualizada aqui: quando o código e esta página discordarem, vale o código.

PregaoForever is the owner's planned auction-house addon for WoW Forever, designed in one session on 2026-11-16 (no code, nothing run in the game). This page keeps three things that outlive the project state: how a design document was checked mechanically before being called done, a notice found in three installed third-party addons and what the agent did about it, and the auction facts read from the Forever client. The design's own state (what waits for the owner) is perishable and lives in `hot.md` and `log.md`.

**Scope:** items are tagged one by one: `[product: wow-modder]` for the gate and the notice decision, `[product: WoW Forever]` for the client facts. At design time nothing here was tested in the game; from the evening of 2026-11-16 the addon (0.1.0) runs in read-only mode in the game and the sections "Auction facts" and "Measured in the game" below carry the first readings (source: PregaoForever Waves 0 to 2 in One Day, the First Night in the Game & a Contract That Fixed Names but Not Types — Session of 2026-11-16 (evening)).

## Key points

### A mechanical gate for a design document, run before calling it done `[product: wow-modder]` (n=1 document; an observed procedure, not proof that it is useful)
- **What the scripts checked.** The 169 review-finding ids in the changes table (`MUDANCAS.md`); that every hypothesis, decision, probe step and invariant cited has a definition; that the 16 game commands fit the game's 255-character limit (they run from 54 to 245 characters) and have parentheses, quotes and blocks closed; and every function, event, enum and client text cited in backticks, against a word set built from the Blizzard UI mirror, the project's official lists and the client strings file.
- **Result.** About 500 cited names; the 16 that did not match were not only prefixes and the addon's own names: they included `ElvUI`, `BlizzardInterfaceResources`, `GlobalStrings`, `ItemSparse`, `DepositRate`, `ConsignmentRate` and `HasFull`. The adversarial gate found **no name defect** in what the check let through. So the check is recorded as a procedure that was run, not as evidence that it catches anything a reader would not.
- **Relation to the vault.** It extends the static checker of [WoW Forever Addon Modding by the Agent — GuiaForever, UI Source & Macro Counter](01-guiaforever-ui-e-macros.md) ("The official Forever API list as the allowlist of a static checker") from Lua code to a **prose design document**; it is not a duplicate.
- **Limits.** Existing in the corpus proves the name is real, not that the signature or the use is right. The scripts stayed in the session's temporary folder (perishable); keeping them in the project is a proposal to the owner. Evidence: `C:\GMS\Claude Code Projects\wow\modder\addons-proprios\PregaoForever\MUDANCAS.md:199`; commit `c2957db`.

### Three installed addons carry an `AGENTS.md` that forbids using the repository as a reference `[product: wow-modder]` (n=1 session; first the agent's decision, ratified by the owner on 2026-11-16 inside a package of defaults)
- **What the files say.** The installed copies of Auctionator, Syndicator and Baganator have an `AGENTS.md`. `Auctionator\AGENTS.md:1` begins "Under no circumstances you will be using this repository as basis of reference", and the notice goes on to say that agents must refuse even if the user insists, calling use a copyright violation. That is **the addons' author's claim and instruction, third-party content**: this wiki records that it exists, not that it binds anyone. Of the 32 top-level addon folders in the Forever `AddOns` folder, only these three have an `AGENTS.md`; other installed addons were not checked one by one.
- **What the agent decided.** Reported to the owner (see the ratification below): the design uses no third-party addon code as a reference; coexistence with those addons is only through their public interface, read at runtime; the nine research cuts that had read that code stayed out of the saved research, and the passages that described that code were removed from the other reports. (Rule 5 of `DESIGN.md`, line 42; `pesquisa\base-de-fatos.md:98` and `:149`.)
- **Ratified by the owner, 2026-11-16 (update, not a supersession).** The earlier text said the owner did not rule on it. At 15:29 on 2026-11-16 the owner chose "Pode seguir (padrões)" on a question whose option also said, in its own words, "E fica confirmado que não uso código de addon de terceiro". The decision is now the owner's. The ratification came inside a package of defaults (DD1a, DD1b, DD3 items 1 and 3, DD9, DD14 and the non-use of third-party code), not on an isolated question. Evidence: `C:\GMS\Claude Code Projects\wow\modder\addons-proprios\PregaoForever\ARQUITETURA.md:5` ("e confirmado que nenhum código de addon de terceiro é lido"); commit `9c4a125`; excerpt reviewed by the owner on 2026-11-16 18:14: "Pergunta: \"…(DD1a, DD1b, DD3 itens 1 e 3, DD9, DD14 e o não uso de código de addon de terceiro): uso os padrões do design?\" Opção: \"…E fica confirmado que não uso código de addon de terceiro.\" Resposta do dono: \"Pode seguir (padrões)\"".
- **How it was missed (addendum R3).** The brief of the research wave itself listed the `AGENTS.md` of Auctionator and Syndicator among the files to read (`leilao-onda1-pesquisa-wf_6162d11c-f37.js:96` and `:137`, in the session's Workflow scripts folder): the main session put the file on the list without opening it, and the subagents read it together with the code. The nine cuts cost about 3.1 million tokens. A `find` or `ls */AGENTS.md` over the folders to be read, before writing the brief, would have caught it.
- **Limits.** n=1; the notice came from three addons by one author. Evidence: `C:\Program Files (x86)\World of Warcraft\_forever_\Interface\AddOns\Auctionator\AGENTS.md:1`; a calibration file of another project, lines 401 to 407, 414 and 415 (the nine cuts, "não usado"); commit `c2957db`.

### Auction facts read from the Forever client (1.60.1 build 70938), partly tested in the game (S0, 16/11/2026) `[product: WoW Forever]`
The fact base is `pesquisa\base-de-fatos.md` in the addon folder, with 16 reports beside it. Prefer its lines 42, 32, 16 and 47 as pointers (the distillate's lines 11, 27 and 49 fall on section headings).
- **Seven auction action functions carry the restriction mark and fail silently** when called outside the allowed context.
- **Search limit.** The documentation limits search by item to 100 calls per minute and asks that it not sweep the whole auction house.
- **Rates and durations.** The client table gives a deposit rate of 5 and a cut rate of 5 at the faction auction houses, and 25 and 15 at the neutral one, with durations of 2, 8 and 24 hours. **The "5/5 and 25/15" reading is an inference** (marked so in the base); Blizzard did not publish the deposit and cut formula.
- **Undercutting.** The client's own tutorial text says there is no need to undercut the price, because an auction posted later at the same price sells first.
- **Custom scripts guard.** `/run` and `/dump` pass through the same guard as the "Allow custom scripts?" warning. Source: `Blizzard_ChatFrameBase/Shared/SlashCommands.lua`, the `/dump` guard at lines 1428 to 1433 and the `/run` guard at line 1404 of the mirror at commit `bebcb6bf` (<https://github.com/Ketho/wow-ui-source-forever/blob/bebcb6bf309cf41b41bd74f8ca651e6a105b2676/Interface/AddOns/Blizzard_ChatFrameBase/Shared/SlashCommands.lua#L1428-L1433>). The gate could not open this link (network); the session read those lines in a temporary local copy of the mirror, which no longer exists.
- **Limits.** The strings file read is from build 70532; the minimum deposit changes at the maintenance of 17/11 by announcement, not by a reading of the client. Evidence: `DESIGN.md:83`; commit `c2957db`.
- **Read in the game by probe S0, 2026-11-16 (n=1 reading, before the maintenance of 17/11; reinforces the facts above; the 16 commands were pasted by the owner, game 1.60.1, build 70938, Interface 16001).** Durations 2, 8 and 24 hours; time-left bands 0 to 1800, 1800 to 7200, 7200 to 43200 and 43200 to 86400 s; the auction accepts copper; minimum deposit 100 copper from both `CalculateItemDeposit` and `CalculateCommodityDeposit` (both answered for a commodity); the buy quote had 26 s left when read (it lasts about 30 s); the client's posting notice says an unsold auction comes back at the maintenance and the deposit is lost; the tip "Auctions posted later (at the same price) are sold first" confirms the basis of the match-the-price rule; rules preset 1 (Enhanced), scripts and addons allowed; the letters B, C, H, I, K, L, M, N, O, P, U and Y and the keys F1 to F5 already have a function in the game; over remote access the interface measures 1950 by 1097 units at scale 0.7 and F3 reaches the game. Evidence: `C:\GMS\Claude Code Projects\wow\modder\addons-proprios\PregaoForever\pesquisa\sonda\S0-2026-11-16.md:10` to `:22` (table of the 16 commands); commit `ea69e41`. ### Measured in the game on the first night, 2026-11-16 (addon 0.1.0, read-only mode) `[product: WoW Forever]`
- **A purchase echoes before the money changes, and the client fires `AUCTION_CANCELED` for the bought auction (item 1, n=1 item purchase, not a commodity; evidence of an inference).** On an item bought through the Blizzard auction screen (3 silver; the purchase was made outside the addon), the Livro row shows the money before equal to the money after, and the Banco shows a `cancel` in the same second; the session read that as `AUCTION_CANCELED`. The order is **inferred from the addon's database** (`seq` 52 buy, 54 cancel; equal money), not from a raw record of the events. The `AUCTION_HOUSE_PURCHASE_COMPLETED` echo thus seems to arrive before `PLAYER_MONEY`, and the cancel was recorded as an owner cancellation by the addon and as "canceled" by probe S9. The fix (read the money before at the echo and wait for the next `PLAYER_MONEY`, or 1 s; ignore `AUCTION_CANCELED` for a bought auction in the session) passed on the bench (80 scenarios) and **has not run in the game yet**. Evidence: `C:\GMS\Claude Code Projects\wow\modder\addons-proprios\PregaoForever\pesquisa\sonda\onda2-2026-11-16.md:19` (section "Banco da noite"); `...\PregaoForever\Ecos.lua:67` and `:89`; `...\PregaoForever\Sonda.lua:149`; commit `ea69e41`; scenario `C:\GMS\Claude Code Projects\wow\modder\ferramentas\guia\casos-pregao\cenarios\unid-livro\livro-15-compra-real-no-cliente.lua`; `node pregao/ler-pregao.mjs <SavedVariables of the Avell>` showed `livro 2 … acoes: buy=1 cancel=1 | origem: … outside=2` (read 18:04, 2026-11-16). The SavedVariables sit in the game folder, outside git.
- **A syntax error at the end of a `.lua` does not stop the later files of the `.toc` from loading (item 3, n=1, a syntax error at the end of the file; reinforces the design's own defence).** With a syntax error put on purpose at the end of `Config.lua` (third file of the `.toc`), `/reload` loaded the 25 following files (the count is the session's): the window opened, the banner `CONFIG ERROR - read only` appeared and the Mine view drew. The defence of the design (`ns.cfg` nil becomes read-only mode) works. Not tested: a runtime error at the top of a file; the second half of S13 (truncated SavedVariables). Evidence: `...\pesquisa\sonda\onda2-2026-11-16.md:13` (section "S13, first half"); record `sonda.S13 = "1|1794861727|70938|config error seen at load, later files loaded"` read at 18:04, 2026-11-16; commit `ea69e41`.
- **S4 timings from key L to `SCAN IDLE` with Auctionator loaded (R1, n=1 per tab, stopwatch by hand on a phone, no `API STALLED`).** 8 s with the Blizzard Buy tab open, 33 s with the Auctions tab, 15 s with the Auctionator Shopping tab. The cause of the 33 s is a hypothesis (the Blizzard screen's query of the own auctions on the same throttle, or the summary of the whole auction only in that breath). The two measures with Auctionator off are still missing (they decide DD12 with three baseline sessions). Evidence: `...\pesquisa\sonda\onda2-2026-11-16.md:9` and `:11`; commit `ea69e41`; owner, 2026-11-16: "S4: 1: 8s 2: 33s 3: 15s".

The position of Auctionator's frame was not read. Evidence: `...\pesquisa\sonda\onda2-2026-11-16.md:17`; the owner's screenshot in the conversation (17:42, 2026-11-16).

### Building the addon `[product: wow-modder]` (n=1 each)
- **Round trip with data recorded by the real code (item 8, new).** The reader outside the game passed the round trip of the 23 grammar examples, but reading a SavedVariables written by the whole addon on the bench (scenario `dados-04`) it found two invalid lines: the ring of snapshots by key (the reader expected text) and the list of session actions (empty). After the fix, the bench file and the game file (186 records) gave 0 invalid. The technique is general; the scope stays in the project until it repeats elsewhere. The answer in numbered stages with one code block per command worked in the sense that the owner pasted all the results as text.
