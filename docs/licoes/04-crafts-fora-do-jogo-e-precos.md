## Key points

### 1. Auctionator prices through the public API, with a 248-character `/run` `[product: WoW Forever]` (n=1 run)
- The Auctionator 341 price database on disk is not readable directly: in `Auctionator.lua`, `AUCTIONATOR_PRICE_DATABASE` holds, per realm, one encoded string (the line had 669,536 characters; **only the transcript proves that number**, it is not in the contract).
- What worked: a `/run` pasted by the owner after a full scan loops over item ids 1 to 300,000, calls `Auctionator.API.v1.GetAuctionPriceByItemID` and `GetAuctionAgeByItemID`, and writes the result to the `ah` key of the database of the owner's GuiaForever addon; `/reload` flushes it to disk and an outside script reads it. Three tricks: text keys (`t[i..""]`) so every row is `["id"] = value,` in the file; age in days packed into the fraction (`price + age/1000`) to fit one value per item; `3e5` instead of the long number. It ran in the game and answered `6876 ok /reload`; the reader found 6,876 prices, 6,654 with age 0.
- **Does not contradict** the `AGENTS.md` decision on [PregaoForever Auction Addon Design — Forever Auction Facts, a Design Gate & a Third-Party AGENTS.md Notice](03-pregaoforever-design-do-leilao.md): only the public interface is used, at runtime.
- **Limits.** n=1 run, client 1.60.1 build 70938, Auctionator 341. The two function names came from the model's prior knowledge, not from reading the addon; the behaviour confirmed them, but the exact meaning of "age 0" is inference. Before the game the command only ran in a simulator (fengari) with a stand-in API, in a temporary file not kept. The list only uses an export up to 6 hours old. Evidence: `C:\GMS\Claude Code Projects\wow\modder\ferramentas\pregao\CONTRATO.md:112` (the command) and `:115` (result in the game); `node baixar-precos.mjs` in that folder → `auctionator: exportacao 2026-11-16T18:04:39.000Z precos=6876 idade0=6654`; `baixar-precos.mjs:57` (`lerExportacao`); `testes\sv-exemplo.lua`; owner, 2026-11-16, about 15:04: image of the game chat with "6876 ok /reload"; commit `286e013`.

### 2. Client tables for recipes and vendor price `[product: WoW Forever]` (one build, Leatherworking only)
From wago.tools, build 1.60.1.70938 (the gate reproduced the counts):
- **Recipes.** `SkillLineAbility` with `SkillLine` 165 has 616 spells; 592 create an item (`SpellEffect` `Effect` 24, item in `EffectItemType`, quantity in `EffectBasePointsF`, 1 in 591 and 2 in one). 110 of them have a product in `Item` but absent from `ItemSparse` and none was listed at the auction: left out. 482 remain. "Leftover from another game version" for the 110 is an inference.
- **Recipe colour.** `TrivialSkillLineRankLow` is the skill at which it turns yellow, `TrivialSkillLineRankHigh` the one at which it turns grey. `MinSkillLineRank` is 1 for all: **the skill to learn at the trainer is not in the client tables.**
- **Recipe by item.** `ItemEffect` with `TriggerType` 6 and the spell id, linked by `ItemXItemEffect`; the item's `RequiredSkillRank` is the required skill. Covers 388 of 482. For these, the gap between the yellow band and the required skill has a 90th percentile of 25 points (**only the contract proves it**: it came from a stray command not kept); the tool uses "yellow minus 25" as the estimate for the other 94.
- **Buy price.** `ItemSparse.BuyPrice` is the price of the lot of `VendorStackCount` units; per unit is the division. Checked against the game: the 386 prices of Auctionator's `AUCTIONATOR_VENDOR_PRICE_CACHE` block all match (227 equal, 159 with a 5% to 20% reputation discount, none divergent).
- **What that block is.** It keeps, in readable text, the per-unit price the vendor **charges**, with reputation discount, for items the owner saw on sale. It is **not** the price the vendor pays (the first contract wrote it as the sell price; see the process note).
- **Sell price to the vendor.** `SellPrice` has no automatic check. The owner read one tooltip: 31s 51c on the Barbaric Leggings, equal to the table's 3151.
- **Limits.** One build; counts for Leatherworking only; sell price checked on one item. Evidence: `CONTRATO.md:67`, `:71`, `:74`, `:83`, `:200`; `node gerar-receitas.mjs --conferir-vendedor` → `comparados=386 iguais=227 desconto=159 divergentes=0`; `node gerar-receitas.mjs && node testes/checar-receitas.mjs` → `receitas=482 itens=625 contagem={"receitas":482,"semItem":24,"semReagente":0,"semItemSparse":110,"comItemReceita":388} erros=0`; `gerar-receitas.mjs:18` and `:113`; commit `7a357d0`; owner, 2026-11-16, about 15:06: "barbaric leggings -> 31s 51c".

### 3. The public hourly price file: format, houses, limits and the owner's house `[product: WoW Forever]`
The repository `RuslanMunasipov/quest-murder-prices` publishes, in the `current` release, files per auction house, updated about once an hour. The owner approved it **by choosing the option that said to approve the public file** ("Fora agora, painel depois (Recomendado)"; transcript lines 181 and 186), not by a separate statement.
- `index.txt` gives, per file, the snapshot time and the SHA-256. `<region>-<house>.txt` has one row per item: type (`c` stackable, `i` item), id, lowest price, 25th percentile, median, units, lots and the 5 cheapest lots. Equipment is in the `i` rows.
- `<house>-sales.txt` gives units sold per day but **only for stackable items** (1,270 `c` items, no `i`): there is no liquidity number for armour. The method is the author's and undocumented.
- `vendors.txt` lists items sold by vendor (declared source: QuestieDB), base 36 with a difference from the previous item, with control items to validate the reading.
- Region US has four Alliance houses (110, 111, 119, 123). **The owner's is 111**, and that holds only for this owner: with his scan, 86% of the 6,448 common items differ by up to 5% from house 111's lowest price, median difference zero; in the other three the median difference is 22% to 40%. The comparison between houses is only in the transcript and the contract.
- The file lags and the market moves: in house 111, Heavy Leather had a lowest price of 1s 97c and 3,154 units at the 12:17 snapshot, 2s 05c and 7,115 at 14:17, and 2s 18c in the owner's scan at 15:04 (**the 12:17 minimums exist only in the transcript**).
- **Limits.** Third-party source, no guarantee it stays up; the meaning of the columns was inferred from the README and the data; the per-type count came from stray commands (numbers in the contract and `estado.md`). Evidence: `CONTRATO.md:96`, `:98`, `:119`, `:122`; `baixar-precos.mjs:108` (SHA-256) and `:174` (vendor list validation); `node baixar-precos.mjs && node testes/checar-precos.mjs` → `publicos=6454 saidas=1324 vendedor=3734 auctionator=6876 erros=0`; `C:\GMS\Claude Code Projects\wow\modder\estado\estado.md:185`; commit `286e013`.

### 4. Client tables for the six crafting professions `[product: WoW Forever]` (n=1 build 1.60.1.71037; 2026-11-23; widens section 2, does not contradict it)
- Section 2 was Leatherworking only, build 70938. On 2026-11-23 the same tables were read for six professions. `SkillLine` ids: Alchemy 171, Blacksmithing 164, Enchanting 333, Engineering 202, Leatherworking 165, Tailoring 197. In `SkillLineAbility`, `AcquireMethod` 1 marks the recipe that comes with the profession (skill 1; Bolt of Linen Cloth, Rough Blasting Powder, Runed Copper Rod; this matches "`MinSkillLineRank` is 1" of section 2) and `AcquireMethod` 3 marks a recipe never learned. **In Alchemy that is 9 recipes (`nunca=9`)**: the six healing potions, Potion of Poison Cleansing, Purification Potion and one with no name in `SpellName` (spell 6619); not "only the six healing potions".
- Enchantments are spells with no effect 24 and with effect 53 or 54 (179 in Enchanting). The required tool is in `SpellTotems` (category in `TotemCategory`, a mask: the Runed Silver Rod serves where the Copper one is asked). The nearby object is `SpellCastingRequirements.RequiresSpellFocus`, named in `SpellFocusObject`; camp objects exist as an item of the same name bought at auction (Tanning Rack, Spinning Wheel, Fermenter, Anarchist's Workbench), while Anvil and Forge are in cities. From build 70938 to 71037 only the Orcish War Leggings changed in the six.
- Limits: one build; "1 comes with it" and "3 never learned" are a reading of the data (the six healing potions match the sources), not checked at the trainer; how long an assembled camp object lasts is not in the client. Evidence: `ferramentas\pregao\gerar-receitas.mjs:16`, `:18`, `:19`, `:216`, `:244`, `:253`; `node gerar-receitas.mjs --profissao todas` → `alchemy: magias=212 receitas=179 iniciais=3 encantamentos=0 nunca=9`; `CONTRATO.md` sections 10.1 and 10.7; commits `fdc8d93`, `5f3d79f`. ### 6. The public price file does not say the ruleset: the map of Forever auction houses, 2026-11-26 `[product: WoW Forever]` (new; complements section 3, no conflict; n=1 collector, measured on the EU only)
Section 3 only says that the owner's house is 111 and does not deal with ruleset. The measurement below is the reading by the author of a third-party repository, not ours.
- **Houses.** Forever has no realms: there is one house per region, ruleset and faction, and the numbers are the same in the US and the EU. Alliance 110, 111, 112, 119, 123; Horde 113, 114, 115, 120, 124; Blackwater 116, 117, 118, 121, 125; 112, 115 and 118 are empty; 122 does not exist.
- **The file does not identify it.** `quest-murder-prices` carries `ruleset=1` and `ruleset_name=-` in every house, so the field says nothing about the ruleset.
- **What was measured (EU, 14/11, one public collector).** Against the TSM data, 113 is Horde PvP and 114 is Horde Normal (100% of prices equal). The rest follows the position in each block of three (PvP, Normal, empty), in line with the API ruleset ids (1 PvP, 2 Normal, 3 Roleplay, 15 Roleplay PvP).
- **In the US the order is an inference by the same numbering, not a measurement.** The owner's house, us-111 (checked against his screen on 16/11), falls as Alliance Normal. His choice of Horde PvP on 2026-11-26 15h40 used us-113.
- **Limits.** n=1 collector; the two Roleplay blocks (119 to 121 and 123 to 125) cannot be told apart; third-party repositories, no guarantee. Evidence: `C:\GMS\Claude Code Projects\wow\comum\referencia\forever.md:112` (commit `c0256d1`); `curl -sL https://github.com/RuslanMunasipov/quest-murder-prices/releases/download/current/us-113.txt | head -5` → `ruleset=1`, `ruleset_name=-`, `house_name=Horde Auction House`; `gh api repos/jofri99/forever-ah-flip/contents/docs/forever-api.md --jq .content | base64 -d | sed -n 17,62p` → "113 PvP-Horde ... 100%", "114 Normal-Horde ... 100%", measured 14/11 against `dynamic-forever-eu`; `gh api repos/prismicious/forever-auction-feed/readme` → "EU PvP Horde auction summaries (house 113)"; owner, 2026-11-26 15h40: "utilizando os preços da Horda PVP como base".
- **How it was found (perishable, `[product: WoW Forever]`, n=1 day, one IP).** The price sites were blocked or gave only the region median; a code search did the work. The page of the Horde PvP US market of ahledger answered 429 to `WebFetch` and to `curl` (title "Vercel Security Checkpoint") and was not worked around; its home page was read. The icy-veins realm page gave 403 to `WebFetch`. `curl -sL -A "Mozilla/5.0" https://timesaver.gg/wow-forever/auction-prices.csv | head -1` answered (the site responded, no workaround) but only with the median by region and faction, no ruleset. `gh search code "namespace dynamic-forever"` found `jofri99/forever-ah-flip`; `gh search code "dynamic-forever-us"` found, among others, `Koollan/forever-market-ledger` and `Estabondotcom/Forever-Market-`. The 429 may also have been a rate limit after two calls in a row. The web-access side is in Claude Code Web Research Access — WebFetch Blocks & Claude in Chrome.
