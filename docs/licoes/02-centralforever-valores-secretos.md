## Key points

### 1. Damage and threat come from the native meter and the threat functions; each function has its own hidden-value mark `[product: WoW Forever]` (n=1 documentation read; not tested in the game)
- **Read in the documentation of build 70938, not tested in the game.** In the Forever an addon does not read the combat log: the official list has no `CombatLogGetCurrentEventInfo`. Damage and DPS come from `C_DamageMeter.GetCombatSessionFromType(session, type)`, marked `SecretWhenInCombat` (values hidden while the addon combat restriction is active); `isLocalPlayer` is `NeverSecret` and `GetSessionDurationSeconds` has no mark.
- **Threat has two predicates by function.** `UnitThreatSituation` and `UnitThreatLeadSituation` are `SecretWhenUnitThreatStateRestricted`: the text says the state is **generally not secret** for a player, pet or ally against the target, boss included (keep the "generally"). `UnitDetailedThreatSituation` as a whole, including the `status` it returns, and `UnitThreatPercentageOfLead` are `SecretWhenUnitThreatValuesRestricted`: readable only against a non-boss target. So the state is read from one function and the percentage from another.
- **What accepts a hidden value coming from an addon** (`SecretArguments = "AllowedWhenTainted"`): `FontString:SetText`, `StatusBar:SetValue` and `SetMinMaxValues`, `Region:SetAlphaFromBoolean`, `AbbreviateNumbers`, `C_StringUtil.RoundToNearestString` and `WrapString`. **What refuses it:** `SetShown`, `SetWidth`, `SetPoint`, `GetThreatStatusColor`.
- **Details and QUI** set the CVar `damageMeterEnabled` to 0 while showing numbers read from the same API (Tercioo/Details-Damage-Meter `core/parser_nocleu.lua:718-722`; zol-wow/QUI `QUI_DamageMeter/damage_meter/damage_meter.lua:3869-3875`). **Read by the session through `gh api`, not checked by the gate.**
- **Expressway has no fixed-width digits:** the "1" advances 256/1000 em, the other digits 536 to 584 (the gate reproduced it by reading the `hmtx` table of the font file).
- Evidence: `C:\GMS\Claude Code Projects\wow\comum\referencia\api-forever.md:122` (section 3f, file and line of each mark; `:128` the CVar, `:129` the two threat predicates, `:133` Expressway); `C:\GMS\Claude Code Projects\wow\modder\ferramentas\guia\api-forever\doc\DamageMeterDocumentation.lua:23`, `:41`, `:97` and `UnitDocumentation.lua:1086`, `:3244`, `:3262`, `:3279` (local copy, outside git, downloaded 2026-11-16); commit `322bf65`; `cd "C:/GMS/Claude Code Projects/wow/modder/ferramentas/guia" && node conferir-doc.mjs` printed `30 de 30 ancoras conferem`.
- **Limits:** what the client actually returns in the open world, a dungeon and a boss, the text the formatters produce, and whether the engine collects with the CVar at 0 are left to the addon's diary. Whether arithmetic and comparison with a hidden value raise an error in addon code is not in the documentation (the bench of item 4 assumes the pessimistic case). The font metric was read from the font table by a subagent and reproduced by the gate; the session did not recheck it.

### 3. Confine the code that touches hidden values to one file, with boxes and drains, and enforce it with a static checker `[product: wow-modder]` (n=1 addon; **never ran in the game**)
- Only `Segredo.lua` calls the combat functions and only it reads the raw value. Each return becomes a box `{ cru, s, tem, n }`: `s` says whether it is hidden (tested before any comparison with `nil`), `n` is the value when readable. The other modules decide only with `s`, `tem` and `n`; display goes through "drains" (functions that hand `cru` to `SetText`, `SetValue` or `SetAlphaFromBoolean`).
- `checar-combate.mjs` got a `--perfil central` with rules R10 (combat function outside the file), R11 (read of `.cru` outside it), R12 (measuring text or reading alpha), R14 (non-existent widget method), R15 (`SetCVar` outside the coexistence module), R16 (`targettarget` and nameplate tokens) and R17 (event outside the closed list).
- **What the owner approved, and what he did not.** Rule 5 of the project (`GuiaForever\ARQUITETURA.md:20`) got exception 2, approved by the owner for this single-file confinement: "Aprovo (Recomendado)" (2026-11-16 05:55 UTC, a closed question). **Limit 3 of `C:\GMS\Claude Code Projects\wow\CLAUDE.md` still stands: never circumvent hidden values or protected functions, not even in the project's own addon.** The path used is the official display channel (`AllowedWhenTainted`). Read "exception 2" as that narrow permission, not as a license.
- Evidence: `C:\GMS\Claude Code Projects\wow\modder\addons-proprios\CentralForever\CONTRATO.md:27` (section 2) and `:68` (3.3); `Segredo.lua:110` (`S.caixa`), `:79` (`S.legivel`), `:433` and `:443` (`SetAlphaFromBoolean`); `checar-combate.mjs:277` (R10), `:282` (R11), `:286` (R16), `:325` (R17), `:347` (R15), `:364` (R12); commit `322bf65`; `node rodar-casos-combate.mjs` printed `todos os 29 casos como esperado`.

### 4. A bench with a hidden-value simulator and an AST rewrite of the code `[product: wow-modder]` (new technique; reinforces the bench as the definition of done; n=1)
- To prove outside the game that the addon does no arithmetic, comparison or boolean test with a hidden value, the bench (fengari, Lua 5.3) uses a simulated value: an empty table with a locked metatable that raises on arithmetic, `<`, concatenation, `#`, index and call, with `type`, `tostring`, `string.format` and `math.*` replaced by versions that recognise it. What a metatable cannot catch (boolean test, `==` and `~=`, table keys) the rewrite catches: a script reads the `.lua` with `luaparse` and wraps conditions in `__B(...)`, equalities in `__EQ(a, b)` and non-literal indexes in `__K(k)`, without changing line numbers. Simulated widgets only have the methods of the official list and follow the documentation's marks (accept or refuse).
- The bench runs 34 scenarios and a matrix that swaps, one at a time, ten unknowns of the client (408 runs). The gate reproduced all four commands.
- Evidence: `ferramentas\guia\bancada\segredo.lua:82` (`type`), `:174` (`__B`), `:178` (`__EQ`), `:182` (`__K`); `ferramentas\guia\bancada\instrumentar.mjs:55`, `:71`, `:77`; `CONTRATO.md:566` (section 13); commit `322bf65`; in `C:/GMS/Claude Code Projects/wow/modder/ferramentas/guia`: `node rodar-casos-segredo.mjs` → `todos os 44 casos como esperado`; `node rodar-central.mjs` → `RESUMO: 34 execucoes, 34 ok, 0 com falha`; `node rodar-central.mjs --matriz` → `RESUMO: 408 execucoes, 408 ok, 0 com falha`; `node rodar-central.mjs --autoteste` printed the self-test line.
- **Limits:** the simulated value is a hypothesis about the client (pessimistic by default); the bench is Lua 5.3 and the game is 5.1; it proves the Lua runs and respects the invariants, not appearance or the real behaviour of the frames. The sabotage test of the bench itself is in AI-Assisted Work Process (2026-11-16 section).

### 9. A junction-linked addon takes a Config change at the next `/reload`; a per-character CVar is not undone by a global list `[product: wow-modder]` (n=1; **nothing seen in the game**)
- UIForever is linked to the game by junction, so any edit to its `Config.lua` enters the game at the next `/reload` or login, even with the game open. The plan put the new UIForever lines (turn off the ElvUI threat bar, move the tooltip) in a step before the new addon was linked: in that gap the owner would have no threat bar and a misplaced tooltip, and the WTF backup would capture an already altered state. Fix: write those lines only at the gate with the game closed, after the backup and together with `dev-link`.
- UIForever writes each CVar once per character and does not restore the value of a removed line. Only one character had `damageMeterEnabled` at 1, so a global list would not return each character's state. The new addon became the owner of that CVar, saving the previous value per character and returning it when it is turned off.
- Evidence: plan `C:\Users\PC-AVELL\.claude\plans\eu-quero-uma-central-fizzy-hopcroft.md:139`; `addons-proprios\UIForever\Config.lua:101` and `:102` (the two lines, with the way back in a comment); `CONTRATO.md:170` (3.8) and `addons-proprios\CentralForever\Convivencia.lua:80`; `estado\estado.md:177` (diary: backup, UIForever lines, `dev-link`, audit); commit `322bf65`.
- **Limits:** n=1. The junction mechanics were not reproduced by the gate, nor was the order of the diary at `estado.md:177`. If the bar disappears and the tooltip moves as calculated, only the next login shows. The finding came from a plan reviewer (AI-Assisted Work Process, 2026-11-16 section).
