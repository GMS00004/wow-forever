### 0.2 Notação

- Tempo `t` em horas, no relógio do servidor. Preços em cobre, inteiros. `x = ln(preço)`.
- Item `i` (chave de item), categoria `g(i)`.
- Foto `k` do item no instante `t_k`: escada `L_k = [(p_j, q_j, n_j)]`, `j = 1..J`, preço crescente; `q_j` = unidades no degrau, `n_j` = número de donos no degrau. Para item não commodity, a escada é montada a partir dos leilões (um degrau por preço de arremate por unidade), e cada leilão guarda id, dono, lance e faixa de tempo.
- As unidades próprias são sempre subtraídas da escada antes de qualquer estimador (o motor sabe o que postou).
- `Qc(p) = Σ_{p_j ≤ p} q_j` (quantidade acumulada até o preço p). `Pq(Q) = min{p_j : Qc(p_j) ≥ Q}` (preço na profundidade Q). `Cv(Q)` = custo de varrer as Q unidades mais baratas.
- `Δ_k = t_k − t_{k−1}` (intervalo entre fotos).
- `limita(v, a, b)` = v restrito a [a, b]. `Φ` = distribuição normal padrão acumulada.

## 1. Valor justo e volatilidade a partir de fotos irregulares da escada

### 1.1 O que estimar

Três números por item, cada um com incerteza e idade:

1. `m_k`: preço robusto da foto k (um número por foto, resistente a isca e a parede).
2. `V`: valor justo corrente, combinação no tempo dos `m_k` e dos preços das vendas inferidas (seção 2).
3. `σ`: três dispersões diferentes, que não devem ser confundidas: `σ_e` (ruído de foto para foto), `σ_h` (quanto o nível anda por raiz de hora) e `σ_stat` (dispersão de longo prazo em torno do nível lento).

O preço mínimo (`p_1`) não serve como valor: uma unidade de isca o move à vontade. A mediana da escada inteira também não serve: a cauda cara nunca vende e uma parede longe da frente a domina. O que vende são as unidades mais baratas, então a referência é a **média aparada das unidades mais baratas, numa janela do tamanho da demanda de algumas horas**.

### 1.2 Fórmulas

Janela de referência (em unidades):

```
N_ref = limita( teto(λ · H_ref),  N_min,  max(N_min, min(N_cap, f_max · Q_tot)) )     se λ é conhecido
N_ref = limita( teto(f_0 · Q_tot), N_min, N_cap )                                     item novo
```

Filtro de isca: o degrau j (e tudo antes dele) é isca quando a quantidade acumulada até j é pequena e há um salto de preço logo depois:

```
isca(j)  ⇔  Qc(p_j) ≤ q_isca   e   p_{j+1} / p_j ≥ 1 + g_isca,      q_isca = max(1, f_isca · N_ref)
```

Preço robusto da foto (média aparada em log, ponderada por unidade, das N_ref unidades mais baratas depois da isca; descarta a fração `α_ap` de cada ponta):

```
m_k = exp( Σ_u w_u · ln p_u / Σ_u w_u ),   u percorre as unidades da janela; w_u = 1 se a posição de u está em [α_ap·N_ref, (1−α_ap)·N_ref], senão 0
```

Dispersão interna da janela (achatamento da escada), usada como sinal de qualidade: `s_k = 1,4826 · MAD ponderado de ln p_u` dentro da janela.

Combinação no tempo, com fotos irregulares (EWMA em log com peso que depende do intervalo e inovação cortada à Huber):

```
w_k   = 1 − exp(−Δ_k / τ_f)
e_k   = x_k − x̂_{k−1},            x_k = ln m_k − ln s_bin(t_k)        (dessazonalizado, seção 8)
x̂_k   = x̂_{k−1} + w_k · limita(e_k, −k_H·σ_e, +k_H·σ_e)
a_k   = (1 − w_k)·a_{k−1} + w_k · min(|e_k|, 3·k_H·σ_e)
σ_e   = max(σ_min, 1,2533 · a_k)                                      (E|e| = σ·√(2/π) na normal)
W2_k  = (1 − w_k)²·W2_{k−1} + w_k²                                     (soma dos pesos ao quadrado)
```

Tamanho efetivo da amostra. Fotos tiradas a um minuto uma da outra são quase a mesma foto; a janela só traz informação nova quando gira. Com tempo de independência `τ_ind = H_ref`:

```
n_ef = min( 1 / W2_k ,  1 + τ_f / τ_ind )
```

Nível lento e dispersões de prazo longo, a partir das medianas diárias `M_d` (mediana dos `x_k` do dia, anel de `N_d` dias):

```
x̂_s    = mediana(M_d, últimos N_d dias)
σ_stat = 1,4826 · MAD(x_k − x̂_s, últimos N_d dias)
σ_dia  = 1,4826 · MAD(M_d − M_{d−1})        σ_h = σ_dia / √24
σ_dia  ← √( (n_d · σ_dia² + n0_σ · σ_cat²) / (n_d + n0_σ) )           (encolhe para a categoria com poucos dias)
```

Variância e intervalo de confiança do nível rápido no instante t (idade = `t − t_k`):

```
var_f(t) = k_IC² · σ_e² / n_ef  +  min(σ_h² · idade, σ_stat²)
IC       = exp( x̂_k ± z_IC · √var_f(t) )
```

O primeiro termo é erro de medida; o segundo é o quanto o mercado pode ter andado desde a última foto. O teto `σ_stat²` reflete que preço de leilão reverte à média: a incerteza não cresce sem limite.

Preço das vendas inferidas. Cada diferença entre fotos (seção 2) entrega pares (preço, unidades vendidas). `x̂_T` é o mesmo EWMA, com constante `τ_T`, alimentado pela média ponderada por unidade dos preços vendidos em cada intervalo; `n_T` conta intervalos com venda (não unidades). `var_T(t) = σ_T² / n_T + min(σ_h² · idade_T, σ_stat²)`.

Valor justo:

```
x_V  = ( x̂_f / var_f + x̂_T / var_T ) / ( 1/var_f + 1/var_T )
σ_V² = 1 / ( 1/var_f + 1/var_T )
V    = exp(x_V) · s_bin(t)                    (volta a sazonalidade da hora)
z_i  = (x̂_f − x̂_s) / σ_stat                  (quão caro ou barato o item está contra o regime)
```

Sem vendas inferidas suficientes (`n_T < n_T_min`), `V = exp(x̂_f)`. Limites de sanidade: `V ≥ v_sell(i)` (o NPC é piso) e, para item fabricável, alerta quando `V > Kc(i)·(1 + m_c)` (custo de produção, seção 5).

Estado do dado pela idade: **fresco** (`idade ≤ A_fresh`), **usável** (`≤ A_stale`, com o IC inflado pela fórmula) e **vencido** (`> A_stale`: bloqueia sinal de compra e pede consulta nova).

### 1.3 Pseudocódigo

```
função preco_robusto(L, λ):                       -- L sem unidades próprias, ordenada
  Q_tot ← Σ q_j ;  se Q_tot = 0: devolve nil, {vazia}
  N_ref ← janela(λ, Q_tot)                         -- fórmula acima
  q_isca ← max(1, f_isca · N_ref)
  j0 ← 1 ; acum ← 0
  para j de 1 até min(J − 1, J_isca):
      acum ← acum + q_j
      se acum > q_isca: pare
      se p_{j+1} / p_j ≥ 1 + g_isca: j0 ← j + 1    -- tudo até j é isca
  lo ← α_ap · N_ref ; hi ← (1 − α_ap) · N_ref
  soma ← 0 ; peso ← 0 ; pos ← 0
  para j de j0 até J enquanto pos < N_ref:
      u ← min(q_j, N_ref − pos)
      dentro ← max(0, min(pos + u, hi) − max(pos, lo))
      soma ← soma + dentro · ln(p_j) ; peso ← peso + dentro
      pos ← pos + u
  devolve soma / peso, {n = pos, rasa = (pos < N_min), iscas = j0 − 1, p_frente = p_{j0}}

função atualiza_valor(E, x, t):                    -- E = estado do item; x já dessazonalizado
  se E.x = nil: E.x ← x ; E.a ← σ_cat·0,8 ; E.σ_e ← σ_cat ; E.W2 ← 1 ; E.t ← t ; devolve
  w ← 1 − exp(−(t − E.t) / τ_f)
  e ← x − E.x
  E.x ← E.x + w · limita(e, −k_H·E.σ_e, k_H·E.σ_e)
  E.a ← (1 − w)·E.a + w · min(|e|, 3·k_H·E.σ_e)
  E.σ_e ← max(σ_min, 1,2533 · E.a)
  E.W2 ← (1 − w)²·E.W2 + w² ; E.t ← t
```

Custo: O(J) por foto, O(1) de estado por item.

### 1.4 Hipóteses

- H1.1 Prioridade de preço: quem compra leva o mais barato; por isso as unidades baratas são as que formam preço.
- H1.2 Isca é pouca quantidade seguida de salto. Parede é muita quantidade num preço só; dentro da janela ela domina a média, e isso é o certo (a parede é o preço de fato enquanto não for consumida).
- H1.3 O ruído de foto para foto é aproximadamente simétrico em log.
- H1.4 O nível anda devagar em relação a `τ_f` fora de quebras de regime (seção 8).

### 1.5 Modos de falha

| Falha | Sintoma | Defesa |
|---|---|---|
| Escada rasa (menos que `N_min` unidades) | `m_k` pula | marca `rasa`, peso `w_k` dividido por 4, IC largo |
| Monopólio (um dono em toda a janela) | `m_k` é o preço que o dono quis | usar `x̂_T` e `x̂_s`; marcar concentração (seção 9) |
| Reset de terceiro | `x̂_f` sobe em degrau, `x̂_T` não acompanha | divergência `x̂_f − x̂_T > 2·σ_e` vira alerta, não valor |
| Isca com quantidade acima de `q_isca` | `m_k` cai | a apara inferior absorve até `α_ap·N_ref`; acima disso é oferta real barata e é tratada como tal |
| Foto incompleta (resposta parcial) | janela cortada | gravar `completa`; foto incompleta não atualiza `x̂` |
| Item não commodity com variações | preços de coisas diferentes na mesma escada | a chave de item precisa separar as variações; sem isso, só sinais de vendedor NPC e de conversão |
| Leilão só de lance | arremate ausente | fica fora da escada de arremate; entra só no sniper de lance |

### 1.6 Dados que a varredura precisa registrar

Por foto: `t` do pedido e da resposta, fonte (resumo, busca, varredura completa), `completa`, `Q_tot`, `J`, os `K_lvl` primeiros degraus (preço, quantidade, donos), a cauda em baldes geométricos de preço, as unidades próprias por degrau, e os derivados `m_k`, `s_k`, `p_frente`, número de degraus de isca. Por dia: mediana, mínimo e máximo de `x_k`, número de fotos, horas cobertas.

### 1.7 Calibração com o diário

- Cobertura do IC: fração dos preços de venda (próprias e inferidas) da hora seguinte que cai dentro do IC. Alvo: `1 − α` nominal. Ajusta `k_IC`.
- `τ_f`, `H_ref`, `α_ap`: na mesa, escolher os que minimizam o erro absoluto de `ln(preço da próxima venda própria) − x_V`, em validação que só usa o passado.
- `g_isca` e `f_isca`: rotular à mão 50 fotos com isca e medir acerto e falso alarme.

## 2. Liquidez: taxa de venda pela diferença entre escadas sucessivas

### 2.1 Ideia central

Entre duas fotos completas do mesmo item, cada degrau ganha ou perde unidades. Quatro eventos produzem isso: venda, cancelamento, expiração e postagem nova (a repostagem é cancelamento seguido de postagem). Só a prioridade de preço permite separar.

Defina, por preço p: sobreviventes `sob(p) = min(q0(p), q1(p))`, perda `per(p) = max(0, q0(p) − q1(p))`, ganho `gan(p) = max(0, q1(p) − q0(p))`. A **fronteira** é o degrau mais barato com sobrevivente:

```
F = min{ p : sob(p) > 0 }
```

**Proposição (fronteira).** Se a compra sempre leva a unidade mais barata e as unidades sobreviventes em F são as mesmas da foto anterior, então toda venda do intervalo ocorreu a preço ≤ F. Prova: os sobreviventes de F estiveram à venda o intervalo todo; em qualquer instante o mais barato disponível custava no máximo F.

Consequências:

- `per(p)` com `p > F` não é venda: é cancelamento ou expiração.
- Tudo que existia abaixo de F sumiu (por definição de F): é venda, salvo cancelamento ou expiração na frente.
- `per(F)` é consumo parcial do degrau da fronteira.
- `gan(p)` com `p < F` é oferta nova que cobriu o preço e ainda não vendeu.

```
S_lo = Σ_{p < F} q0(p) + per(F) − R_frente            (R_frente = unidades da frente identificadas como repostagem)
```

`S_lo` é **limite inferior** das vendas, por dois motivos que não aparecem na diferença: unidades postadas e vendidas dentro do intervalo, e vendas compensadas por postagem nova no mesmo preço. A simulação (0.3) mostra o tamanho: a perda cresce com o intervalo e com o giro, chega a quase metade com 30 minutos e a 60% com 60 minutos num mercado de 30 un/h.

### 2.2 Correção do viés

Fator de correção `ξ ≥ 1`, função de `u = λ·Δ / l_f`, a demanda do intervalo medida em lotes típicos da frente (`l_f` = tamanho médio dos ganhos que cobrem ou igualam a frente):

```
Ŝ = ξ(u) · (1 − π_cf) · S_lo,        ξ(u) = 1 + ξ_a · u^ξ_b       (inicial: ξ_a = 0,5, ξ_b = 0,8)
```

A forma inicial sai do mercado sintético (as duas configurações colapsam em u: `ξ ≈ 1,2` em `u ≈ 0,4`; `1,5` em `u ≈ 1`; `2,0` em `u ≈ 2,5`). `π_cf` é a probabilidade de um sumiço na frente ser cancelamento. A regra de projeto que sai daqui: para manter o viés abaixo de 20%, o intervalo entre fotos de um item em foco precisa ser

```
Δ_alvo(i) ≤ u_alvo · l_f / λ          (u_alvo = 0,4)
```

Exemplo: 30 un/h e lotes de 6 dá 5 minutos; 3 un/h e lotes de 3 dá 24 minutos.

A oferta nova observada também é limite inferior, pela mesma razão. A contabilidade fecha assim (as unidades vendidas sem serem vistas foram postadas sem serem vistas):

```
ν̂·Δ = Σ_p gan(p) − R_total + (ξ − 1)·(1 − π_cf)·S_lo        (R_total = ganhos casados como repostagem; não são oferta nova)
```

### 2.3 Cancelamento, expiração e repostagem

**Repostagem.** Uma perda em `p_a` casada com um ganho em `p_b < p_a` no mesmo intervalo (ou no seguinte) é cancelamento seguido de postagem. Critério com nome de dono (itens): mesmo dono, mesma chave, id novo, preço menor. Critério sem nome (commodity agregada): `|gan(p_b) − per(p_a)| ≤ tol_rep · per(p_a)`, `p_b` dentro de `g_rep` abaixo da frente anterior, e queda de 1 no número de donos em `p_a` com alta de 1 em `p_b`. O casamento sem nome é probabilístico: peso `π_rep_q`.

**Expiração em commodity (sem tempo restante por unidade).** Guardar coortes por degrau: cada ganho cria `(preço, quantidade, t_lo, t_hi)` com o intervalo em que apareceu. Uma perda acima da fronteira no intervalo `(t0, t1]` é candidata a expiração quando, para alguma duração `D ∈ 𝒟`, `[t_lo + D, t_hi + D]` cruza `(t0, t1]`. Peso = fração do cruzamento. Caso contrário é cancelamento. Unidades que já estavam lá na primeira foto têm idade desconhecida: classe "indeterminado".

**Expiração em item (com faixa de tempo restante).** Cada observação da faixa `[lo_b, hi_b)` no instante `t_k` restringe o fim do leilão: `E_lo = max_k(t_k + lo_b)`, `E_hi = min_k(t_k + hi_b)`. A troca de faixa entre duas fotos aperta muito o intervalo. Quando o id some em `(t0, t1]`:

```
t1 < E_lo                     → não pode ter expirado: venda ou cancelamento
[t0, t1] cruza [E_lo, E_hi]   → π_exp = comprimento do cruzamento / (E_hi − E_lo)
venda × cancelamento          → repostagem casada: cancelamento
                                senão P(venda) = π_v(posto), posto = quantas unidades mais baratas da mesma chave sobreviveram
                                (inicial: posto 0 → 0,85; 1 a 3 → 0,5; mais → 0,15)
com lance e t1 ≥ E_lo         → venda por lance ao preço do lance
```

Em item não commodity o comprador pode não levar o mais barato (variações), então a proposição da fronteira vale só como probabilidade (`π_v`).

### 2.4 Da contagem à taxa

Modelo: pedidos chegam em processo de Poisson; cada pedido leva um lote de tamanho aleatório B. A contagem do intervalo é Poisson composta: média `λ·Δ`, variância `λ·Δ·φ_λ`, com `φ_λ = E[B²]/E[B]` (índice de dispersão). Ignorar `φ_λ` dá intervalos de confiança estreitos demais.

Estimador Gama-Poisson com esquecimento, exposição sazonal e sobredispersão:

```
decai = exp(−Δ / τ_λ)
SA ← SA·decai + Ŝ                                  (vendas, decaídas)
SB ← SB·decai + Δ·s_bin                            (exposição em horas sazonais, seção 8)
SF ← SF·decai + (Ŝ − λ·Δ·s_bin)² / max(λ·Δ·s_bin, 0,5) ;  SN ← SN·decai + 1
φ_λ = max(1, SF / max(SN − 1, 1))
forma = n0_λ·λ_cat + SA/φ_λ ;   taxa = n0_λ + SB/φ_λ
λ̂ = forma / taxa
quantil(z) = (forma/taxa) · (1 − 1/(9·forma) + z/(3·√forma))³        (Wilson-Hilferty)
```

`λ_lo` e `λ_hi` são os quantis `z = ∓z_λ`. O prior `(n0_λ·λ_cat, n0_λ)` é a taxa da categoria com `n0_λ` horas de peso.

Regras de censura:

- **Intervalo longo** (`Δ > Δ_max(i) = limita(H_ref, Δ_lo, Δ_hi)`) ou foto incompleta: o par não entra em SA nem em SB. Buraco de observação não é exposição com zero venda.
- **Sem sobrevivente** (F não existe): tudo que se via girou. `Ŝ` entra como limite inferior e o intervalo é marcado censurado; se a parcela censurada da exposição recente passar de `ψ_cens`, λ é exibido como "pelo menos" e o agendador encurta o intervalo.
- **Sem estoque** nas duas fotos: demanda não observável; não conta como exposição.
- **Varrida** (alguém limpou a escada): `Ŝ` acima de `k_cap·λ·Δ·s_bin` é cortado nesse teto e o excesso vira evento de varrida (seções 8 e 9). Demanda orgânica e reset de terceiro não se misturam.

Demanda em função do preço: `λ(p) = λ·G(p/V)`, `G(x) = min(1, x^(−ε_d))`. `ε_d` sai na mesa, por regressão de Poisson das vendas por intervalo contra `ln(p_frente/V)`, encolhida para o prior da categoria.

A taxa de saída sem venda das unidades de trás: `γ̂ = (unidades sumidas acima de F) / (unidade-hora exposta acima de F)`, mesmo esquema de decaimento.

### 2.5 Pseudocódigo

```
função diferenca(L0, L1):                          -- ambas completas, sem unidades próprias
  F ← menor p com min(q0(p), q1(p)) > 0 ; censurado ← (F não existe)
  pf0 ← preço da frente de L0 (depois do filtro de isca)
  para cada p na união dos preços, crescente:
      per ← max(0, q0(p) − q1(p)) ; gan ← max(0, q1(p) − q0(p))
      se censurado ou p < F:  frente[p] ← q0(p)                       -- sumiu na frente
      senão se p = F:        frente[p] ← per
      senão se per > 0:      atras[p] ← per                           -- cancelamento ou expiração
      se gan > 0: novo[p] ← gan ; classe ← (p < pf0: cobre | p = pf0: iguala | senão: atras, razão p/pf0)
  casa_repostagens(frente, atras, novo)            -- move unidades casadas para R_frente, R_atras
  classifica_expiracao(atras, coortes)
  devolve {F, censurado, S_lo = Σ frente − R_frente, vendas = [(p, frente[p])], X_cancel, X_expira, novo}

função atualiza_liquidez(E, d, Δ, s_bin):
  se d.incompleta ou Δ > Δ_max(E) ou d.sem_estoque: devolve
  u ← E.λ·Δ / max(E.l_f, 1)
  S ← (1 + ξ_a·u^ξ_b) · (1 − π_cf) · d.S_lo
  teto ← max(S_piso, k_cap·E.λ·Δ·s_bin)
  se S > teto: registra_varrida(E, S − teto) ; S ← teto
  ... acumula SA, SB, SF, SN e recalcula λ̂, φ_λ, λ_lo, λ_hi como em 2.4
```

### 2.6 Hipóteses

- H2.1 Prioridade de preço na compra (por mecânica em commodity, a confirmar; por comportamento em item).
- H2.2 As unidades sobreviventes de um degrau são as mesmas (mudança mínima). Falha quando um degrau vende e é reposto no mesmo preço dentro do intervalo; o efeito é subcontar, já coberto por ξ.
- H2.3 Cancelamento na frente é raro (`π_cf` pequeno): quem cancela costuma ser quem foi coberto.
- H2.4 A escada veio completa nas duas fotos.

### 2.7 Modos de falha

| Falha | Efeito | Defesa |
|---|---|---|
| Intervalo longo | subconta vendas (40% a 60 min no sintético) | `Δ_alvo`, correção ξ, descarte acima de `Δ_max` |
| Cancelamento na frente tratado como venda | superconta | `π_cf`, casamento de repostagem |
| Varrida de terceiro | λ infla | teto `k_cap` e evento separado |
| Resposta parcial ou throttle no meio | sumiço falso | exigir `completa` nas duas fotos |
| Mesma quantidade vendida e reposta em F | venda invisível | ξ |
| Regra de ordem entre preços iguais desconhecida | não afeta a contagem agregada, só a fila (seção 3) | parâmetro Ω |

### 2.8 Dados que a varredura precisa registrar

Por diferença: `t0`, `t1`, F, `censurado`, `S_lo`, lista (preço, unidades) das vendas inferidas, unidades sumidas atrás divididas em cancelamento, expiração, repostagem e indeterminado, ganhos por classe (cobre, iguala, atrás com a razão), `l_f`, preço da frente nas duas fotos, número de donos na frente. Para itens: por id de leilão, primeira e última vez visto, faixas observadas, dono, lance.

### 2.9 Calibração com o diário

- **Subamostragem**: numa sessão com fotos densas (1 a 2 minutos) de alguns itens, recalcular as vendas usando uma foto a cada 5, 15, 30 e 60 minutos. A razão entre a série densa e a subamostrada é ξ medido, por classe de u. É a calibração mais importante da seção.
- **Vendas próprias**: o que vendeu de fato enquanto estava na frente dá uma taxa de execução sem inferência; comparar com `λ̂` por item.
- **Compras próprias**: toda compra do dono é uma venda de terceiro com preço e hora conhecidos; conferir se a diferença seguinte a classificou como venda.
- `π_cf`: fração dos sumiços da frente seguidos de reaparecimento do mesmo dono mais barato (itens, onde há nome).

## 3. Probabilidade e tempo de venda de uma unidade postada a p com q unidades na frente

### 3.1 Modelo

Postamos n unidades ao preço p com duração D. A nossa unidade vende quando a demanda consome tudo que tem prioridade sobre ela. Três fluxos mexem na fila da frente:

1. **Demanda** que alcança o preço p: `λ_p = λ · s̄ · G(p/V)` unidades por hora, em pedidos de dispersão `φ_λ` (`s̄` = fator sazonal médio do período, seção 8).
2. **Entrada na frente**: concorrentes que postam com prioridade sobre nós, `ν_f(p)` unidades por hora, em lotes de dispersão `φ_ν = E[L²]/E[L]`.
3. **Saída sem venda** de quem está na frente (cancela ou expira), taxa `γ` por unidade.

Fila inicial, conforme a regra de ordem entre preços iguais Ω:

```
q(p) = Qc(p − tick) + q_emp ,   q_emp = q(p) inteiro se Ω = FIFO ou desconhecida (pior caso)
                                         0 se Ω = LIFO
                                         q(p)/2 se Ω = aleatória
q_ef = q · exp(−γ · min(D, q/λ_p) / 2)                       (desconto pela saída sem venda)
```

Entrada na frente, a partir das classes de oferta nova medidas na seção 2 (`π_cobre + π_iguala + π_atras = 1`):

```
ν_f(p) = ν · [ π_cobre · Ψ(min(p, p_frente)/V) + π_iguala · e(p) + π_atras · H_b(p/p_frente) ]
e(p)   = 1 se p > p_frente ;  se p = p_frente: 1 (LIFO), 0 (FIFO), 0,5 (aleatória)
H_b(r) = fração das postagens "atrás" com razão de preço menor que r  (0 para r ≤ 1)
Ψ(x)   = fração do fluxo que cobre e que continua cobrindo com a frente em x·V
         inicial: Ψ(x) = limita((x − x_piso)/(1 − x_piso), 0, 1)
```

**Fato estrutural.** Em regime estacionário a escada não cresce nem some, então `ν = λ + cancelamentos + expirações ≥ λ`. A razão de cobertura `ρ = ν_f/λ_p` na frente fica perto de 1 (com 40% a 70% da oferta nova cobrindo e ν entre 1,2 e 2 vezes λ, ρ cai entre 0,5 e 1,4). A posição na frente é passageira por construção: é isso que faz a repostagem ser a alavanca principal e é por isso que a aproximação precisa ser boa justamente perto de `ρ = 1`.

### 3.2 Fórmulas

A fila é um processo que desce com a demanda e sobe com a cobertura; a venda é a primeira passagem por zero.

**(a) Sem cobertura e pedidos unitários (exata).** O tempo até a (q+1)-ésima unidade demandada é Erlang:

```
P(T ≤ D) = 1 − Σ_{k=0}^{q} e^{−λ_p·D} (λ_p·D)^k / k!
```

**(b) Sem cobertura, pedidos em lote.** Aproximação gama (Wilson-Hilferty):

```
k = λ_p·D / φ_λ ;  x = (q_ef + 0,5) / φ_λ
P_dem = 1 − Φ( ( (x/k)^(1/3) − (1 − 1/(9k)) ) / √(1/(9k)) )
```

`P_dem` é cota superior de qualquer caso com cobertura: concorrente só atrasa.

**(c) Com cobertura, fluxo granular** (lotes pequenos em relação à fila): difusão com deriva `m = λ_p − ν_f` e variância `s² = λ_p·φ_λ + ν_f·φ_ν` por hora; primeira passagem com distribuição gaussiana inversa. A barreira leva a correção de ultrapassagem `φ_λ/2` (o pedido que nos alcança passa do ponto):

```
a    = q_ef + 0,5 + φ_λ/2
P_GI = Φ( (m·D − a) / (s·√D) ) + exp(2·m·a / s²) · Φ( −(a + m·D) / (s·√D) )
E[T] = a / m      (só se m > 0)          Var[T] = a·s² / m³
```

O segundo termo precisa ser calculado em log quando `2·m·a/s² > 30` (`ln Φ(−z) ≈ −z²/2 − ln z − 0,919` para `z > 5`).

**(d) Cobertura maior que a demanda (`ν_f > λ_p`).** A venda só acontece por sorte, e a chance de vender algum dia decai exponencialmente com a fila (cota de Lundberg, exata para tamanhos exponenciais):

```
η   = (ν_f − λ_p) / (λ_p·φ_ν/2 + ν_f·φ_λ/2)
P_∞ = (1 − η·φ_λ/2) · exp(−η · (q_ef + 0,5))
```

Com pedidos e lotes unitários isso reproduz `(λ_p/ν_f)^(q+1)`. Com lotes de 10 na frente e `ν_f = 2·λ_p`, vinte unidades na frente dão `P_∞ ≈ 0,13`: sentar atrás de fila com cobertura alta é quase não postar.

**(e) Concorrente reativo.** Se um concorrente cobre o nosso preço depois de um tempo de reação de média `τ_r` (exponencial), a chance de vender uma unidade antes de ser coberto é

```
P_ciclo = ( λ_p·τ_r / (1 + λ_p·τ_r) )^(q+1)
```

Com `λ_p·τ_r ≪ 1` (ele reage mais rápido do que a demanda chega), cobrir de novo não compra tempo. Com `K_r` concorrentes reativos de cadência parecida com a nossa, a fração do tempo na frente é cerca de `1/(K_r + 1)` e a demanda efetiva é `λ_p/(K_r + 1)`.

**(f) Forma principal: tabela adimensional.** As fórmulas (c) e (d) são aproximações de tráfego pesado e erram quando os lotes que entram na frente são grandes em relação à fila (erro de até 0,27 no teste). O modelo exato depende só de quatro números:

```
A = (q_ef + 0,5) / (λ_p·D)        fila em unidades da demanda do horizonte
ρ = ν_f / λ_p                     razão de cobertura
β = φ_λ / (2·λ_p·D)               tamanho do pedido
ℓ = φ_ν / (2·λ_p·D)               tamanho do lote que cobre
P_tab = Tab[A, ρ, β, ℓ]           interpolação linear em A e ρ, linear em ln β e ln ℓ
```

A tabela é calculada uma vez fora do jogo, por simulação do modelo (não depende de item nem de servidor), e embarcada como dado. No teste: 6.270 entradas, erro médio de interpolação 0,010, máximo 0,113 com grade grosseira; a redução do problema discreto para os quatro números errou no máximo 0,013.

**Reserva sem tabela:** `P_fb = min(P_GI, P_dem, P_∞ se ν_f > λ_p)`.

**Lote de n unidades e tempo médio:**

```
P̄(n)        = [ P(q) + 4·P(q + (n−1)/2) + P(q + n − 1) ] / 6                       (Simpson nas posições do lote)
E[min(T,D)] = (D/8) · [ 1 + 3·(1 − P(D/3)) + 3·(1 − P(2D/3)) + (1 − P(D)) ]        (Simpson 3/8 no tempo)
```

**Intensidade variável no tempo:** trocar `λ_p·D` por `Λ(D) = λ·G·Σ_b s_b·h_b(D)` (horas de D em cada caixa sazonal b), e o mesmo para ν.

**Recalibração empírica** (a última camada, sempre ligada): `logit(P_cal) = a0_cal + a1_cal · logit(P_modelo)`, por classe de liquidez.

### 3.3 Pseudocódigo

```
função P_venda(i, p, q, D):
  λp ← E.λ · saz_media(t, D) · G(p / V)
  νf ← E.ν · ( π_cobre·Ψ(min(p, pf)/V) + π_iguala·e(p) + π_atras·H_b(p/pf) )
  se concorrente_reativo(i): devolve P_reativo(i, p, q, D, λp)       -- seção 9
  qe ← q · exp(−E.γ · min(D, q / max(λp, 1e-9)) / 2)
  se λp·D < 1e-6: devolve 0
  se νf = 0 e E.φ_λ ≤ 1,05 e q ≤ 200: P ← erlang(q, λp·D)
  senão se tabela: P ← Tab((qe+0,5)/(λp·D), νf/λp, E.φ_λ/(2·λp·D), E.φ_ν/(2·λp·D))
  senão: P ← min(P_GI(...), P_dem(...), νf > λp e P_inf(...) ou 1)
  devolve logistica(a0_cal + a1_cal · logit(limita(P, 0,001, 0,999)))
```

### 3.4 Hipóteses

- H3.1 Demanda e cobertura são fluxos independentes, estacionários dentro do horizonte (corrigidos pela sazonalidade).
- H3.2 A prioridade é só preço e a regra Ω; ninguém compra pulando a fila.
- H3.3 O nosso lote é pequeno diante do mercado (não muda `λ` nem `ν`). Para lote grande, ver reset (seção 6).
- H3.4 Os concorrentes não reagem a nós em particular, salvo os marcados como reativos.

### 3.5 Modos de falha

| Falha | Efeito | Defesa |
|---|---|---|
| Lote grande entra na frente | as fórmulas (c) e (d) superestimam a venda | tabela; cota `P_dem`; recalibração |
| Cobridor em minutos | P real é `P_ciclo`, muito menor | detecção da seção 9 troca a fórmula |
| `λ` subestimado pelo viés da seção 2 | P subestimado, preço baixo demais | correção ξ; recalibração pelo diário |
| Fim de semana, patch | intensidades mudam no meio do leilão | `Λ(D)` sazonal; alarme de regime congela |
| Ω errada | fila errada ao igualar | medir Ω (Incógnitas); até lá, pior caso |
| Parede cancelada | venda mais rápida que o previsto | lado seguro; sem defesa |

### 3.6 Dados a registrar

Por postagem própria: item, preço, n, D, fila q no instante, `p_frente`, `λ_p`, `ν_f`, `φ_λ`, `φ_ν`, P prevista (bruta e recalibrada), e o desfecho: vendido (com o intervalo de fotos em que o estado mudou), expirado ou cancelado (com a hora). Cada vez que a fila na frente de um leilão próprio muda, a nova fila e a hora.

### 3.7 Calibração

- Curva de confiabilidade: postagens agrupadas por P prevista (10 faixas) contra a frequência de venda; índice de Brier por semana.
- `a0_cal`, `a1_cal`: regressão logística do desfecho contra `logit(P_modelo)` nas últimas `N_cal` postagens, por classe de liquidez; começam em (0, 1).
- `Ψ`, `H_b`, `π_cobre`, `π_iguala`: frequências dos ganhos classificados na seção 2.
- `τ_r`: seção 9.

## 4. Preço e duração ótimos de postagem

### 4.1 Valor de uma unidade a vender

Custos de uma postagem: depósito `d(i, D, n)` pago na hora (`d_u = d/n` por unidade), devolvido na fração `r_s` se vender, `r_x` se expirar, `r_c` se for cancelado; corte `c` sobre o preço de venda; custo de atenção do dono `κ_post` por ação; custo de carregar `h` por unidade por hora.

Se a unidade não vende, ela volta e é postada de novo. Com mercado estacionário entre ciclos, o número de ciclos até vender é geométrico de média `1/P`. Somando o ciclo que vende e os `(1−P)/P` que falham:

```
W(p, D) = p·(1 − c)
          − (1 − r_s)·d_u                              depósito não devolvido na venda
          − ((1 − P)/P)·(1 − r_x)·d_u                  depósitos perdidos nos ciclos que expiram
          − κ_post / (n·P)                             ações de postagem (uma por lote por ciclo)
          − h · E[min(T, D)] / P                       custo de carregar até vender
com P = P̄(n) da seção 3 ,   h = ρ_cap · V · (1 + idade/τ_age)      (seção 7)
T_tot = E[min(T, D)] / P                               tempo esperado até vender
```

`W* = max_{p, D} W(p, D)` é o **valor de liquidação por leilão** do item. Ele é a moeda comum do motor: precifica postagem, sinal de compra (seção 5), reset (seção 6) e marcação do estoque (seção 7).

**O preço ótimo não depende do que foi pago pelo item.** O custo de aquisição não aparece em W. Estoque comprado caro é precificado pelo mercado de agora.

### 4.2 Conjunto finito de candidatos

Entre dois degraus vizinhos, subir o preço não muda a fila; logo o melhor preço de cada vão é o topo dele. Os candidatos são:

```
cobrir o degrau j:    p_j − tick                 para j = 1..K_lvl      (fica na frente do degrau j)
igualar o degrau j:   p_j                        para j = 1..K_lvl      (vale conforme Ω)
âncoras de valor:     V_lo · {0,9; 1,0; 1,1; 1,25}                      (escada vazia, rala ou toda fora de preço)
```

São no máximo `(2·K_lvl + 4)·|𝒟|` avaliações de W. Candidatos abaixo do piso `max(v_sell, U_alt)/(1 − c)` são descartados.

### 4.3 As decisões, lidas em W

- **Cobrir** (`p_1 − tick`, fila zero): ganha quando a fila do primeiro degrau é grande em relação a `λ_p·D`. Sob FIFO é a escolha padrão contra degrau com fila.
- **Igualar** (`p_1`): sob LIFO domina cobrir (mesma posição, um tick a mais, e não empurra o preço para baixo). Sob FIFO só ganha quando a fila do degrau é pequena (`A` quase não muda) ou quando o concorrente da frente é reativo e cobrir dispara guerra (seção 9).
- **Ficar atrás** (`p_j − tick` com j > 1): ganha quando os degraus da frente são ralos e há um salto de preço antes de uma parede. O candidato natural é `p_parede − tick`: não é preciso ser o primeiro, basta estar na frente da parede. Postar acima de uma parede de `Q_w` unidades exige `A ≥ Q_w/(λ_p·D)`; com `A > 1` e `ρ` perto de 1, P desaba.
- **Cobrir fundo** (bem abaixo da frente): só quando `ρ ≥ 1` na frente por causa de cobridores com piso conhecido; o candidato é logo abaixo do piso deles (`Ψ = 0`), se W ainda for o maior.
- **Não postar**: quando `W* ≤ max(v_sell, U_conv, W_espera) + m_hist`, ou `T_tot > H_max`. `W_espera = E[W*(t + Δ_e)] − h·Δ_e` usa a sazonalidade (por exemplo, guardar para o pico da semana).

### 4.4 Duração

Para cada `D ∈ 𝒟` calcula-se W. Depósito zero ou devolvido na expiração: a mais longa sempre (menos cliques). Depósito proporcional à duração e perdido na expiração: a duração curta ganha quando `P(D)` satura cedo (vende nas primeiras horas ou é enterrado).

### 4.5 Tamanho do lote

Postar todo o estoque de uma vez mostra uma parede e convida cobertura. Regra: lote do tamanho da demanda esperada enquanto estivermos na frente,

```
n* = limita( teto(s_lot · λ_p · T_frente), 1, estoque ),   T_frente = l_f / (ν · π_cobre · Ψ)   ou τ_r se há reativo
```

e avaliar W para `n ∈ {n*, 2·n*, estoque}` (o custo de clique por unidade cai com n, o depósito e a exposição sobem).

### 4.6 Cancelar e repostar

Leilão ativo: preço p, tempo restante `D_r`, fila atual q, depósito por unidade já pago `d_u`. Sejam `P = P̄` e `T_m = E[min(T, D_r)]` nessas condições.

```
EV_fica    = P·(p·(1−c) + r_s·d_u) + (1 − P)·(W* + r_x·d_u) − h·T_m
EV_cancela = r_c·d_u − κ_cancel + W*
Δ_canc     = P·(W* − p·(1−c)) + d_u·(r_c − r_s·P − r_x·(1 − P)) + h·T_m − κ_cancel
cancelar  ⇔  Δ_canc > m_hist
```

Limites: com `P → 0`, cancela-se se carregar até expirar custa mais que o clique e a diferença de depósito; com `P → 1`, nunca. Taxa de cancelamento, se existir, entra como `r_c` negativo.

### 4.7 Pseudocódigo

```
função melhor_postagem(i, estoque, L):
  cand ← candidatos(L, V_lo, K_lvl) filtrados pelo piso
  melhor ← {W = −∞}
  para cada p em cand, D em 𝒟, n em lotes(i, p):
      q ← fila(L, p, Ω)
      P ← media_lote(P_venda, i, p, q, n, D) ; se P < P_min: continue
      Tm ← tempo_medio(i, p, q, n, D)
      du ← d(i, D, n) / n
      W ← p·(1−c) − (1−r_s)·du − ((1−P)/P)·(1−r_x)·du − κ_post/(n·P) − h(i)·Tm/P
      se W > melhor.W: melhor ← {p, D, n, W, P, T_tot = Tm/P}
  alt ← max(v_sell(i), U_conv(i), W_espera(i))
  se melhor.W ≤ alt + m_hist ou melhor.T_tot > H_max: devolve NAO_POSTAR(alt)
  devolve melhor

função rever_leilao(a):                            -- a = leilão próprio ativo
  m ← melhor_postagem(a.item, a.n, escada sem a)
  calcula Δ_canc com m.W ; se Δ_canc > m_hist: recomenda CANCELAR_E_REPOSTAR(m)
```

### 4.8 Hipóteses, modos de falha, dados e calibração

- Hipóteses: mercado estacionário entre ciclos (otimista se o item está em queda: usar `V_lo` nas âncoras e o alarme de regime); `κ_post` e `h` constantes no ciclo.
- Falhas: P mal calibrada desloca o preço de forma sistemática (para cima se superestima); `d` errado em item de depósito alto inverte a escolha de duração; escada velha (candidatos de uma foto vencida). Defesas: recalibração da seção 3, depósito lido do jogo na hora, exigir foto fresca (`A_exec`) antes de recomendar.
- Dados: toda recomendação gravada com candidatos avaliados, W de cada um, a escolha do dono (seguiu ou não) e o desfecho.
- Calibração: comparar `W*` previsto com o líquido realizado por unidade (preço × (1−c) − depósitos perdidos − cliques × κ); a razão média por estratégia é `η_real` (seção 7). `κ_post`, `κ_cancel` e `κ_buy` saem do tempo medido por ação no diário vezes o lucro por hora alvo.

## 5. Sinais de compra

### 5.1 Regra única

Todo sinal compara o custo de comprar com o **valor de saída conservador** do que foi comprado, calculado **na escada que sobra depois da compra**:

```
U_lcb(i, n | L') = max( W*_lcb(i, n | L') ,  v_sell(i) ,  U_conv_lcb(i) )
W*_lcb           = W* da seção 4 com V → V_lo = V·exp(−z_c·σ_V),  λ → λ_lo,  ν → ν_hi
EV               = η_real[estratégia] · n · U_lcb − Custo − κ_buy · cliques
comprar  ⇔  EV ≥ max(M_abs, μ_min · Custo)   e   limites da seção 7   e   foto com idade ≤ A_exec
```

Calcular a saída na escada pós-compra é o que separa pechincha de queda de regime: se depois de comprar as unidades baratas ainda sobra muita oferta barata, `W*` cai sozinho e o sinal some.

A fila de recomendações é ordenada por `EV / cliques` (o evento de hardware é o gargalo, P6), com desempate por `EV / Custo`.

Pseudocódigo comum a sniper, flip e reset raso (muda só a profundidade k e a etiqueta da estratégia):

```
função avalia_compra(i, L, estratégia):              -- devolve a melhor compra do item, ou nil
  melhor ← nil ; n ← 0 ; custo ← 0
  para k de 1 até min(J, K_flip):                    -- degraus mais baratos, um a um
      u ← min(q_k, n_max(i, p_k) − n) ; se u ≤ 0: pare        -- tetos da seção 7
      n ← n + u ; custo ← custo + u·p_k
      L' ← L sem as n unidades mais baratas
      saida ← n · max( W*_lcb(i, n | L'), v_sell(i), U_conv_lcb(i) )
      EV ← η_real[estratégia]·saida − custo − κ_buy·cliques(k)
      se EV ≥ max(M_abs, μ_min·custo) e (melhor = nil ou EV > melhor.EV):
          melhor ← {k, n, custo, EV, por_clique = EV/cliques(k)}
  devolve melhor
```

### 5.2 Sniper (arremate abaixo de uma fração do valor justo)

```
comprar o degrau j enquanto   p_j ≤ a_max = U_lcb(i, n_acum | L') / (1 + μ_min) − κ_buy/n_j
θ_s(i) = a_max / V                                   (a "fração do valor justo" é derivada, não fixa)
```

Exemplo ilustrativo (c = 5% como pista, `σ_V` = 8%, `z_c` = 1, custos de postagem 2%, `μ_min` = 10%): `θ_s ≈ 0,95 · 0,923 · 0,98 / 1,10 ≈ 0,78`. A fração cai com volatilidade, custo e incerteza; por isso um limiar fixo para todos os itens é errado.

Guardas: `λ_lo ≥ λ_min`; `T_tot ≤ H_max`; quantidade `≤ n_max` (seção 7); **guarda de regime**: se a profundidade a preço `≤ a_max` passa de `k_crash · λ · H_ref`, não é pechincha, é preço novo: comprar só o lote de sondagem `n_sonda` e levantar alarme (seção 8).

### 5.3 Flip (comprar a frente e repostar no vão)

Comprar os degraus 1..k e repostar no melhor preço da escada que sobra (em geral `p_{k+1} − tick`):

```
EV_k = η_real · n_k · W*_lcb(i, n_k | L sem os degraus 1..k) − Cv(n_k) − cliques·κ
k* = argmax_k EV_k ,  k ≤ K_flip
condição necessária:  p_{k+1} / p̄_k > (1 + μ_min) / (1 − c) + custos de postagem por unidade / p̄_k
```

O flip não depende de V; depende do formato da escada (o vão) e de `λ_p − ν_f` no preço de repostagem. Flip e sniper são o mesmo cálculo com k pequeno; reset é o mesmo com k grande (seção 6).

### 5.4 Arbitragem contra o vendedor NPC

- **Leilão para NPC**: `p_j < v_sell(i)`. Sem corte, sem depósito, sem risco de preço. `EV = Σ (v_sell − p_j)·q_j − κ_buy·cliques − κ_npc`. Limiar: `EV ≥ M_npc` (cobre a ida ao NPC e o espaço de bolsa). Não leva margem de incerteza.
- **NPC para leilão**: `v_buy(i)·(1 + μ_min) < W*_lcb(i)`. Quantidade limitada pelo estoque do NPC e por `s_cap·λ_lo·H_max`. Se o item é de estoque infinito no NPC, `v_buy` é teto duro do preço de leilão e entra no valor justo como limite.

### 5.5 Arbitragem de conversão (produção e desencanto), com custo recursivo

Custo de obter e valor de saída, ambos por unidade, definidos por recursão:

```
Kc(i, n) = min(  Cv_i(n)/n ,                                        comprar no leilão (custo médio na profundidade n)
                 v_buy(i) ,                                         comprar do NPC
                 min_r [ ( Σ_m a_{r,m}·Kc(m, a_{r,m}·n/y_r) + κ_craft(r) ) / y_r ]  )       fabricar pela receita r

U(i)     = max(  W*_lcb(i) ,  v_sell(i) ,
                 max_r [ Σ_o π_{r,o}·y_{r,o}·U(o) − κ_craft(r) ] ,                           destruir (desencanto e afins)
                 max_r [ ( y_r·U(produto_r) − Σ_{m≠i} a_{r,m}·Kc(m) − κ_craft(r) ) / a_{r,i} ]  )   usar como insumo

Lucro(r, n) = n·y_r·U(produto_r) − Σ_m n·a_{r,m}·Kc(m, n·a_{r,m}) − n·κ_craft(r)
σ_Lucro²    = (n·y_r)²·σ_U² + Σ_m (n·a_{r,m})²·σ_Kc,m²                                         (independência, aproximação)
sinal  ⇔  Lucro − z_c·σ_Lucro ≥ max(M_abs, μ_min·custo dos insumos)
```

`a_{r,m}` = quantidade do insumo m; `y_r` = rendimento esperado (inclui procs); `π_{r,o}·y_{r,o}` = probabilidade e quantidade de cada saída de uma destruição. A quantidade é limitada pelos dois lados: profundidade dos insumos (o custo marginal sobe com n) e absorção do produto (`n·y_r ≤ s_cap·λ_lo(produto)·H_max`). Receita com recarga: o lucro é por recarga, e a recarga vale o melhor lucro entre as receitas que a dividem.

```
função custo_obter(i, n, pilha):
  se memo_K[i] válido: devolve memo_K[i]
  se i ∈ pilha ou |pilha| ≥ P_max: devolve +∞                      -- ciclo ou fundo demais
  melhor ← custo_medio_escada(i, n)                                -- +∞ sem profundidade
  se v_buy(i): melhor ← min(melhor, v_buy(i))
  para cada receita r que produz i:
      c ← κ_craft(r)
      para cada (m, a) em insumos(r): c ← c + a · custo_obter(m, a·n/y_r, pilha ∪ {i})
      melhor ← min(melhor, c / y_r)
  memo_K[i] ← melhor ; devolve melhor
```

As tabelas de receita, rendimento e saída de desencanto do Forever são dados a levantar; as probabilidades de desencanto começam como contagens do próprio diário com prior de Dirichlet.

### 5.6 Sniper de lance

Leilão com lance mínimo b baixo e pouco tempo restante. Ganha-se só se ninguém cobrir o lance até o fim:

```
EV_lance = π_w(b, faixa) · (U_lcb − b) − ρ_cap · b · T_trava(faixa) − κ_bid
π_w      = 1 − (1 − π_faixa) · limita(1 − b/(θ_o·V), 0, 1)
teto     : b_max = U_lcb / (1 + μ_min)
```

`π_faixa` = chance base de ninguém mais dar lance até o fim naquela faixa de tempo; `θ_o·V` = teto típico dos outros licitantes; `T_trava` = tempo em que o ouro fica preso (ponto médio da faixa). Regras: dar sempre o lance mínimo; se for coberto, recalcular com o novo mínimo e parar em `b_max`; se o arremate também passa no sniper, escolher o maior entre `U_lcb − arremate` (certo) e `EV_lance`.

### 5.7 Hipóteses, modos de falha, dados e calibração

| Sinal | Hipótese que o sustenta | Falha típica | Defesa |
|---|---|---|---|
| Sniper | V está certo e a pechincha é rala | V velho ou regime caindo: compra-se o preço novo | saída na escada pós-compra, guarda de regime, `A_exec` |
| Flip | `λ_p > ν_f` no vão | o vão fecha com oferta nova | P da seção 3 com `ν_hi`; lote `≤ s_cap·λ·H_max` |
| NPC | `v_sell` e `v_buy` lidos certo | preço com desconto de reputação, estoque limitado | ler do jogo na hora |
| Conversão | receita e rendimento certos; produto vende | produto sem liquidez; custo marginal ignorado | `Kc` na profundidade; limite pela absorção |
| Lance | ninguém cobre | prorrogação por lance tardio; outro sniper | `π_faixa` do diário; teto `b_max` |

Maldição do vencedor: os sinais com maior EV previsto são, em média, aqueles em que V está superestimado. `η_real` (razão entre EV realizado e previsto, por estratégia, medida no diário) entra multiplicando; começa em 0,5.

Dados a registrar por sinal: tipo, item, escada usada (idade), V, `σ_V`, λ, U previsto, custo, EV, se o dono executou, se a compra pegou (ou "já tinha sumido"), e a ligação com as vendas posteriores do mesmo lote. Calibração: `η_real` por estratégia; `π_faixa` e `θ_o` pela fração de lances ganhos por faixa; `μ_min` e `M_abs` pelo lucro por clique alvo.

## 6. Análise de reset

### 6.1 Definições

Reset de profundidade k: comprar os degraus 1..k e repostar tudo (mais o estoque próprio `n_0`) num preço-alvo.

```
Q_T = Σ_{j≤k} q_j                 unidades compradas
C_T = Cv(Q_T) ,  p̄_T = C_T/Q_T   custo de limpar a escada e preço médio pago
Q   = Q_T + n_0                   unidades a vender no alvo
p_R = min( p_{k+1} − tick , teto_R(i) )
teto_R(i) = min( Kc_fab(i)·(1 + m_c) , v_buy(i) se o NPC vende )
```

O teto pelo custo de produção é central: acima dele os fabricantes inundam o mercado.

Demanda e oferta no preço-alvo, com elasticidades:

```
λ_R = λ_lo · s̄ · (p_R/V)^(−ε_d)              venda esperada por hora no alvo
ν_R = ν_hi · s̄_ν · (p_R/V)^(+ε_s) · π_R       oferta nova por hora que entra abaixo do alvo
N_nova(H_R) = ν_R·H_R ± z_λ·√(ν_R·φ_ν·H_R)    entrada esperada de oferta nova no horizonte
```

`π_R` = fração da oferta nova que entra abaixo de `p_R` (quem ancora no preço antigo entra toda abaixo). `ε_s` capta a oferta latente: estoque em bolsa e banco que só aparece quando o preço sobe.

### 6.2 Quanto se vende no alvo: três modelos

```
pessimista (fluido, postar e esperar):   Z_pes = min( Q , max(0, λ_R − ν_R)·H_R )
central (rateio, repostando como a média dos concorrentes):
                                         Z_cen = Q · min( 1 , λ_R·H_R / (Q + ν_R·H_R) )
passivo exato do modelo da seção 3:      Z_pas = Σ_{u=1}^{Q} P(fila u−1, horizonte H_R; λ_R, ν_R)
```

No rateio, cada unidade à venda no alvo (nossa ou nova) tem a mesma chance de ser a vendida; é o que acontece quando todos se cobrem por um tick e a ordem vira sorteio.

### 6.3 Lucro e fração de equilíbrio

Seja `W_liq` o valor de liquidação por unidade se o alvo falhar (`W*_lcb` no mercado normal). Contra a linha de base de não fazer nada:

```
Π(k) = Z·(p_R·(1−c) − W_liq)  −  Q_T·(p̄_T − W_liq)  −  Dep  −  κ·cliques  −  ρ_cap·C_T·T_R/2
f*   = Q_T·(p̄_T − W_liq) / ( Q·(p_R·(1−c) − W_liq) )        fração de Q que precisa vender no alvo para empatar
T_R  = prazo = menor t com venda acumulada = Z   (no rateio: H_R se Z < Q)
capital preso = C_T no início; capital-hora ≈ C_T·T_R/2
```

Derivação: depois do reset, Z unidades rendem `p_R·(1−c)` e `Q − Z` rendem `W_liq`; antes, `n_0` rendiam `W_liq`. A diferença menos `C_T` dá a fórmula.

Com o rateio, `Z/Q ≥ f*` vira duas condições fechadas:

```
(1)  λ_R / ν_R > f*                     o aproveitamento no preço-alvo tem que superar a fração de equilíbrio
(2)  Q ≤ Q_max = H_R · (λ_R/f* − ν_R)   tamanho máximo do reset
```

E o ágio sustentável no modelo fluido tem cota: `λ_R > ν_R ⇔ p_R/V < (λ_lo / (ν_hi·π_R))^(1/(ε_d + ε_s))`. Como em regime estacionário `ν ≥ λ` (seção 3), esse ágio é menor que 1 para quase todo item líquido: **reset de item líquido não tem valor esperado positivo no modelo pessimista**. Ele só fecha (a) em item de oferta restrita (`ν` bem abaixo de `λ`, a escada é estoque acumulado), (b) em janela de sazonalidade favorável (demanda de pico com entrada de oferta baixa) ou (c) quando o "alvo" é só o preço normal e a escada está deprimida abaixo dele, que é o sniper em escala.

Exemplo ilustrativo (números inventados): `λ = 20/h`, `ν = 22/h`, ágio 1,4, `ε_d = 2`, `ε_s = 1`, `π_R = 0,9` dão `λ_R = 10,2` e `ν_R = 27,7`. Pessimista: `Z = 0`. Com `p̄_T = 1,05·V`, `W_liq = 0,93·V` e c = 5% (pista), `f* = 0,12/0,40 = 0,30`; aproveitamento `0,37 > 0,30`, mas `Q_max = 6,3·H_R`: em 24 horas, 151 unidades, menos de oito horas da demanda normal. Escada mais funda que isso não fecha nem no modelo central.

### 6.4 Quando o reset tem valor esperado positivo

Todas as condições, com λ no quantil baixo e ν no quantil alto:

1. `Π_cen(k) ≥ max(M_abs, μ_reset·C_T)` e `Π_pes(k) ≥ −L_reset` (perda limitada no cenário ruim).
2. `λ_R/ν_R > f*·(1 + m_f)` e `Q ≤ Q_max`.
3. `p_R ≤ teto_R(i)`.
4. `C_T ≤ w_reset·B` e dentro dos tetos da seção 7.
5. Escada completa e fresca (`idade ≤ A_exec`), refeita logo antes de cada compra.
6. Nenhum dono de estoque fundo entre os degraus comprados (seção 9): ele reposta no alvo com mais unidades e `ν_R` explode.
7. Sem alarme de regime aberto no item ou na categoria.

Reset parcial: enumerar k e escolher o maior `Π`. Defender o reset (comprar quem cobre) não precisa de regra própria: cada compra de defesa é um flip avaliado na escada do momento.

### 6.5 Pseudocódigo

```
função avalia_reset(i, L, n0):
  melhor ← nil ; Q_T ← 0 ; C_T ← 0
  para k de 1 até min(J − 1, K_reset):
      Q_T ← Q_T + q_k ; C_T ← C_T + p_k·q_k
      se C_T > w_reset·B: pare
      pR ← min(p_{k+1} − tick, teto_R(i)) ; se pR·(1−c) ≤ W_liq: continue
      λR ← λ_lo·s̄·(pR/V)^(−ε_d) ; νR ← ν_hi·s̄_ν·(pR/V)^(ε_s)·π_R
      Q ← Q_T + n0
      fstar ← Q_T·(C_T/Q_T − W_liq) / (Q·(pR·(1−c) − W_liq))
      Zc ← Q·min(1, λR·H_R/(Q + νR·H_R)) ; Zp ← min(Q, max(0, λR − νR)·H_R)
      Πc ← lucro(Zc) ; Πp ← lucro(Zp)
      se λR/νR > fstar·(1 + m_f) e Πc ≥ max(M_abs, μ_reset·C_T) e Πp ≥ −L_reset e (melhor = nil ou Πc > melhor.Π):
          melhor ← {k, pR, Q_T, C_T, Π = Πc, Π_pes = Πp, prazo, capital = C_T}
  devolve melhor
```

### 6.6 Hipóteses, modos de falha, dados e calibração

- Hipóteses: elasticidades constantes na faixa do ágio; a oferta latente se comporta como `ε_s`; o mercado não percebe o reset como evento (ninguém despeja por pânico ou oportunismo além de `ε_s`).
- Falhas: oferta latente maior que a modelada (o risco dominante); fabricantes entram acima do custo; outro jogador reseta junto ou cobre o alvo em minutos; a escada tinha unidades não vistas (foto incompleta); demanda some no preço novo (`ε_d` subestimada). Perda típica quando falha: corte mais a diferença entre o preço médio pago e a liquidação, sobre `Q_T`.
- Dados: cada reset (próprio ou de terceiro, detectado como varrida na seção 2) vira um episódio: escada antes, preço-alvo, série de `λ`, `ν` e preço da frente nas 48 horas seguintes.
- Calibração: `ε_s` e `ε_d` pela regressão, na mesa, de `ln(ν)` e `ln(λ)` por intervalo contra `ln(p_frente/x̂_s)`, usando os episódios; `π_R` pela fração dos ganhos abaixo do alvo nos episódios. Até haver 5 episódios por categoria, usar os priores pessimistas e exigir confirmação do dono.

## 7. Tamanho de posição e risco

### 7.1 Banca e marcação

```
B = ouro disponível + Σ_i estoque_i · W*_lcb(i)            (estoque marcado a valor de liquidação, nunca a custo)
```

### 7.2 Fração de Kelly com desconto pela incerteza

Para uma compra de custo unitário a, com valor de saída central `U_med` (o mesmo cálculo de `U_lcb` com V, λ e ν nos valores centrais):

```
μ_r  = (η_real·U_med − a) / a                    retorno esperado
σ_r² = σ_h²·T_tot + σ_x²                         risco: o mercado anda enquanto carregamos, mais dispersão de execução
s_μ² = σ_V²                                      incerteza da própria estimativa
f    = k_K · μ_r / (σ_r² + s_μ²)                 fração da banca
```

A incerteza do parâmetro soma na variância (é o resultado de Kelly com média incerta); `k_K < 1` cobre erro de modelo. Com fração `k_K` de Kelly, a chance de a banca cair algum dia para a fração x do valor atual é

```
P(queda até x·B) = x^(2/k_K − 1)             k_K = 1: 50% de cair à metade; 0,5: 12,5%; 0,25: 0,8%
```

Aposta binária (lance): `f = k_K·(π_w/perda − (1−π_w)/ganho)`, ganho e perda como fração do apostado.

### 7.3 Tetos

```
n_max(i) = piso( min(
     f·B / a ,                                          Kelly
     w_item·B / a − estoque_i ,                         por item
     (w_cat·B − exposição da categoria) / a ,           por categoria (risco correlacionado: patch, raide)
     (w_tot·B − exposição total) / a ,                  estoque total; o resto é reserva para pechincha
     s_cap·λ_lo·H_max − estoque_i ,                     por dias de volume: não comprar mais do que se consegue vender
     x_vol·λ·24 − comprado_hoje_i                       por dia de volume: não ser o mercado
) )
```

Arbitragem sem risco (NPC) tem `σ = 0` e Kelly infinito; valem só os tetos.

### 7.4 Envelhecimento e liquidação

O custo de carregar sobe com a idade do lote e com a escassez de capital, e a seção 4 baixa o preço sozinha:

```
h(i, idade) = ρ_cap · V · (1 + idade/τ_age) · (1 + k_esc · [estoque total acima de w_tot·B])
```

Regras por idade do lote (em múltiplos do tempo esperado de venda no momento da compra, `T_tot0`):

- idade > `A_1·T_tot0`: reavaliar V e λ do item (a tese pode estar errada) e repostar pelo W do momento, ignorando o custo.
- idade > `A_2·T_tot0`, ou `T_tot > H_max`: liquidar pela melhor rota entre NPC, conversão e leilão com `h` multiplicado por `k_liq`, em parcelas de `s_cap·λ` por período (não despejar).
- stop por regime: `x̂_f` abaixo do preço de entrada em mais de `ℓ_stop` com alarme de regime aberto: liquidar em parcelas, sem esperar a idade.

### 7.5 Perda máxima diária e disjuntores

```
PnL_dia = realizado no dia + (marcação do estoque agora − marcação na virada do dia)
PnL_dia ≤ −ℓ_dia·B        → modo só venda até a virada (sinais de compra suspensos; o dono pode sobrepor)
PnL_dia ≤ −ℓ_dia·B/2      → aviso
perda por item no dia ≤ −ℓ_item·B → item bloqueado para compra por 24 h
```

Disjuntores de dados, que suspendem compra sem depender de prejuízo: `θ_b` ou mais dos itens de uma categoria fora de `z_b` desvios (seção 8); fotos incompletas em sequência; relógio ou throttle anômalo; `N_seq` compras seguidas que "já tinham sumido".

### 7.6 Pseudocódigo

```
função tamanho(i, a, U_med, T_tot):
  μ ← (η_real·U_med − a)/a ; se μ ≤ 0: devolve 0
  f ← k_K·μ / (σ_h²·T_tot + σ_x² + σ_V²)
  n ← min dos seis tetos de 7.3
  se modo_so_venda ou bloqueado(i): devolve 0
  devolve max(0, piso(n))
```

### 7.7 Hipóteses, modos de falha, dados e calibração

- Hipóteses: retornos de itens de categorias diferentes pouco correlacionados; `W*_lcb` é um preço em que dá para sair.
- Falhas: choque comum (patch) atinge todas as categorias; banca mal medida (ouro em outro personagem ou no correio); Kelly é muito sensível a `μ_r` superestimado (por isso `η_real` e `k_K ≤ 0,5`); item sem liquidez marcado a um `W*` que não existe (teto por dias de volume).
- Dados: lotes com data, custo, estratégia de origem e marcação diária; PnL diário realizado e marcado; cada disparo de teto ou disjuntor.
- Calibração: `η_real` por estratégia a cada semana; `k_K` sobe de 0,25 para 0,5 só quando a curva de confiabilidade (seção 3) e a cobertura do IC (seção 1) estiverem dentro do alvo por duas semanas; `σ_x` é o desvio do líquido realizado contra `U_med`.

## 8. Sazonalidade e mudança de regime com poucos dados

### 8.1 Caixas e encolhimento hierárquico

Caixa `b(t)` = (bloco de 4 horas, dia da semana): 42 caixas. Com poucos dias, cada caixa de cada item foi vista uma ou duas vezes; o fator do item é quase todo emprestado da categoria, e o da categoria, do global.

Fator multiplicativo da taxa (vale para λ e, com contadores próprios, para ν). `S_{i,b}` = vendas inferidas do item na caixa; `E_{i,b}` = horas de exposição na caixa; ambos com decaimento `τ_saz`:

```
global:     ŝ_{0,b} = ( n0_0·1        + Σ_i S_{i,b}      ) / ( n0_0 + Σ_i λ_i·E_{i,b} )
categoria:  ŝ_{g,b} = ( n0_g·ŝ_{0,b}  + Σ_{i∈g} S_{i,b}  ) / ( n0_g + Σ_{i∈g} λ_i·E_{i,b} )
item:       ŝ_{i,b} = ( n0_s·ŝ_{g,b}  + S_{i,b}          ) / ( n0_s + λ_i·E_{i,b} )
normaliza:  ŝ_{·,b} ← ŝ_{·,b} / média_b(ŝ_{·,b})
```

É a média a posteriori Gama-Poisson: com `m = λ_i·E_{i,b}` vendas esperadas, o peso do dado do item é `m/(n0_s + m)`. `n0_s` é medido em vendas esperadas.

Fator do preço (aditivo em log), com `ȳ_{i,b}` = média de `x_k − x̂_f` na caixa e `n_{i,b}` fotos independentes:

```
ŷ_{i,b} = w·ȳ_{i,b} + (1 − w)·ŷ_{g,b} ,   w = n_{i,b} / (n_{i,b} + n0_y) ;   s_bin de preço = exp(ŷ_{i,b})
```

O desvio é medido contra o nível rápido, não contra o lento: nas primeiras semanas de um servidor novo o nível tem tendência (a economia amadurece), e medir contra o nível lento confundiria tendência com hora do dia.

Uso: dessazonalizar `x_k` antes do EWMA (seção 1), a exposição `Δ·s_bin` (seção 2), `Λ(D)` (seção 3), `W_espera` (seção 4) e a janela do reset (seção 6).

### 8.2 Detecção de quebra

Quatro detectores, do mais fraco ao mais forte:

**(a) CUSUM do preço por item**, sobre a mediana dessazonalizada de cada bloco de 4 horas (as fotos dentro do bloco são correlacionadas; o bloco é a observação):

```
z_bl = (M_b − x̂_s) / σ_stat
g⁺ ← max(0, g⁺ + z_bl − k_c) ;  g⁻ ← max(0, g⁻ − z_bl − k_c) ;  alarme se g⁺ > h_c ou g⁻ > h_c
```

Com `k_c = 0,5` detecta deslocamento de um desvio; `h_c = 4` e `5` dão, pelas tabelas clássicas de CUSUM (a conferir por simulação na mesa), cerca de 170 e 470 observações entre alarmes falsos por lado. Com centenas de itens haverá alarmes falsos todo dia: o alarme de item só congela o item.

**(b) CUSUM de Poisson da taxa**, para alta (`r = 2`) e queda (`r = 0,5`) de λ:

```
g ← max(0, g + Ŝ·ln r − (r − 1)·λ·Δ·s_bin) ;  alarme se g > h_P
```

**(c) Amplitude na categoria** (o detector que funciona com poucos dados, porque junta itens):

```
f_g(t) = fração dos itens da categoria com |z_i| > z_b ,   alarme se f_g ≥ θ_b com pelo menos n_b itens
```

Sob independência e normalidade, `P(|z| > 2) ≈ 0,05`; com 10 itens, 3 ou mais fora ao mesmo tempo tem probabilidade 0,012 por avaliação; com 20 itens, 6 ou mais, cerca de 0,0003.

**(d) Calendário do dono**: datas conhecidas (patch, abertura de raide, reset semanal) armam o motor antes: `k_K` cai pela metade, IC inflado, `τ_f` reduzido.

### 8.3 Reação ao alarme

```
ao alarmar (item ou categoria):
   suspende sinais de compra do escopo por T_cool (o dono pode sobrepor)
   W2 ← max(W2, 0,5)                      -- n_ef cai para 2: o nível rápido reaprende
   SA, SB, S_{i,b}, E_{i,b} ← ϕ_q · (os mesmos)   -- a memória de liquidez perde peso
   x̂_s recomeça com os dias depois da quebra; os anteriores ficam marcados "regime anterior"
   grava o evento (hora, detector, z, f_g)
```

### 8.4 Pseudocódigo

```
função fecha_bloco(E, b):                          -- ao fim de cada bloco de 4 h com fotos
  M ← mediana(x do bloco) ; z ← (M − E.x_s)/E.σ_stat
  E.gp ← max(0, E.gp + z − k_c) ; E.gm ← max(0, E.gm − z − k_c)
  atualiza S_{i,b}, E_{i,b}, ȳ_{i,b}, n_{i,b}
  se E.gp > h_c ou E.gm > h_c: alarma(E, "preço") ; E.gp ← 0 ; E.gm ← 0
função varre_categoria(g):
  f ← fração de itens de g com |z_i| > z_b ; se n(g) ≥ n_b e f ≥ θ_b: alarma(g, "amplitude")
```

### 8.5 Hipóteses, modos de falha, dados e calibração

- Hipóteses: o padrão semanal é multiplicativo e comum à categoria; as quebras são deslocamentos de nível ou de taxa.
- Falhas: servidor novo tem tendência forte e o padrão semanal ainda não se formou (as 42 caixas ficam quase todas no valor global); as fotos existem só nas horas em que o dono joga (caixas nunca vistas ficam no prior e isso precisa aparecer na interface); feriado ou evento confundido com quebra; categoria mal definida mistura itens de padrões diferentes.
- Dados: por item e caixa, `S`, `E`, `ȳ`, `n`; por bloco, mediana e z; eventos de alarme; o calendário informado pelo dono.
- Calibração: `n0_s`, `n0_g`, `n0_y` pelo melhor erro de previsão fora da amostra (verossimilhança de Poisson das vendas por caixa), na mesa; `h_c`, `h_P`, `θ_b` pela taxa de alarme falso medida em semanas sem evento conhecido.

## 9. Concorrentes

### 9.1 O que dá para ver

- **Itens** (P3): dono por leilão. Dá para montar perfil por (dono, item).
- **Commodities** (P2): só o número de donos por degrau. Sem nome, o perfil é do degrau: um degrau com `n_j = 1` é um vendedor só, e a "assinatura" (tamanho do lote, distância de cobertura, cadência) substitui o nome. Se a API também entregar nomes em commodity, vale o perfil por dono (Incógnitas).

### 9.2 Medidas por (dono ou assinatura, item)

**Tempo de reação à cobertura.** Evento: o concorrente X estava na frente, alguém o cobriu na janela `(t_a, t_b]` e X reapareceu na frente na janela `(t_c, t_d]`. O tempo de reação é censurado por intervalo: `R ∈ [max(0, t_c − t_b), t_d − t_a]`; usa-se o ponto médio. Se X não voltou até o fim da observação, `R > R_cens` (censura à direita). Estimador de máxima verossimilhança exponencial com censura:

```
τ̂_r = Σ_eventos min(R_j, R_cens,j) / (número de eventos com resposta observada)
```

A resolução é limitada pela cadência das fotos: não se distingue reação mais rápida que `Δ`. Para classificar "cobre em minutos" é preciso `Δ ≤ R_fast/2` no item, pelo menos durante a medição.

**Classes:**

| Classe | Regra |
|---|---|
| Cobridor rápido | `τ̂_r ≤ R_fast` com pelo menos `n_r` eventos |
| Robô provável | cobridor rápido, com coeficiente de variação dos intervalos de repostagem `< CV_bot` e presença em mais de `h_bot` horas do dia |
| Cobridor de sessão | reage em horas, em faixas horárias fixas |
| Âncora | nunca muda o preço; posta no próprio preço |
| Estoque fundo | repõe o mesmo degrau depois de vender, mais de `n_rep` vezes em 24 h |

**Outras medidas:** horas de presença (histograma de 24 caixas); estilo de cobertura (por tick, por percentual, iguala); piso observado `x_piso(X)` = menor razão preço/V em que X ainda cobriu; participação nas unidades da janela de referência; concentração da janela (`HHI = Σ participação²`).

**Parede:** degrau j é parede quando

```
q_j ≥ max( k_wall · λ · H_ref ,  f_wall · N_ref )    e   n_j ≤ 2
tempo para consumir tudo até a parede, inclusive:  T_parede = (Qc(p_j) + 0,5 + φ_λ/2) / (λ_p − ν_f)   se positivo
```

**Isca:** pontuação

```
isca(j) = [Qc(p_j) ≤ q_isca] · [p_{j+1}/p_j ≥ 1 + g_isca] · (1 + [mesmo dono ou assinatura numa parede acima]) + repetições nas últimas 24 h
```

Isca com parede do mesmo dono acima é o padrão de quem quer que os outros cubram a isca para comprar barato.

**Padrão de repostagem:** sequência de (some em p, reaparece em p' < p) do mesmo dono; período médio, coeficiente de variação e horas ativas.

### 9.3 Como isso muda a decisão de postar

| Situação detectada | Efeito no motor |
|---|---|
| Cobridor rápido na frente | P da seção 3 vira `P_ciclo` com `τ̂_r`; cobrir por um tick tem valor quase nulo se `λ_p·τ̂_r ≪ 1`. Opções avaliadas por W: logo abaixo do piso dele (`Ψ = 0`), igualar (se Ω favorece), postar fora das horas de presença dele com duração curta, ou não postar. |
| Vários reativos (`K_r`) | demanda efetiva `λ_p/(K_r + 1)`; o custo de clique por repostagem entra em W; em geral o item sai da lista. |
| Parede com `T_parede ≤ H_max` | candidato `p_parede − tick` (seção 4); nunca acima dela. |
| Parede de dono de estoque fundo | reset bloqueado (seção 6); ficar à frente dela só com margem. |
| Isca | fora do valor justo (seção 1) e fora dos candidatos de preço; continua valendo como sinal de compra se passar no sniper. |
| Janela concentrada (`HHI > HHI_max`) | IC do valor justo inflado; sinais de flip e reset pedem confirmação. |
| Âncora barata | é oferta real: entra no valor e pode ser alvo de flip. |

Guerra de cobertura é guerra de desgaste. Cada repostagem nossa custa um clique (P6) e talvez depósito; a de um robô custa zero. O motor não entra: se W com `P_ciclo` não paga os cliques, a recomendação é sair do item.

### 9.4 Pseudocódigo

```
função atualiza_concorrentes(i, L0, L1, t0, t1):
  para cada dono (ou assinatura de degrau com n_j = 1) X presente em L0 ou L1:
      era_frente ← X na frente de L0 ; e_frente ← X na frente de L1
      se era_frente e não e_frente e alguém mais barato em L1: abre evento_coberto(X, t0, t1)
      se e_frente e X tem evento aberto: fecha com R = ponto médio ; acumula soma_R, n_resp
      se X sumiu de p e apareceu em p' < p: registra repostagem(X, t1, p, p')
      atualiza presença[hora], piso(X), participação
  para cada degrau j: marca parede(j), isca(j)
  classe(X) ← regras da tabela ; K_r ← número de cobridores rápidos ativos agora
```

### 9.5 Hipóteses, modos de falha, dados e calibração

- Hipóteses: o comportamento de um dono é estável de um dia para o outro; em commodity, assinatura de degrau identifica o vendedor.
- Falhas: mesmo jogador com vários personagens (subestima concentração); dois vendedores no mesmo degrau (assinatura some); cadência de fotos lenta demais para medir `τ_r` (tudo parece "lento"); o nosso próprio comportamento provoca a reação medida (o perfil vale para quando nós postamos, que é o caso de interesse).
- Dados: por (dono, item): eventos de cobertura com janelas, repostagens, presença por hora, menor razão de preço, unidades postadas por dia. Tabela limitada aos `N_donos` mais ativos por item.
- Calibração: `R_fast` e `n_r` pela taxa de acerto da previsão "serei coberto em menos de 10 minutos" nas postagens próprias; `k_wall` e `f_wall` conferindo se as paredes marcadas de fato seguraram o preço.

## 10. Backtest e avaliação a partir das fotos gravadas

### 10.1 Princípio

Repassar as fotos gravadas em ordem de tempo. Em cada instante o motor enxerga só o que estava gravado até ali e roda as mesmas funções de decisão do jogo. O resultado são lotes hipotéticos (compra, postagem, venda) com custos completos.

### 10.2 Modelo de execução

**Compra.** Recomendação no instante `t_k` sobre a escada `L_k`. O dono leva `δ_react` para agir.

```
se existe foto em t' ∈ [t_k + δ_react, t_k + δ_max]:
     preenche min(n pedido, unidades ainda presentes em L(t') a preço ≤ limite), ao preço listado
senão: não preenche (padrão conservador)   ou   preenche com probabilidade exp(−δ_react/τ_vida(desconto))
```

`τ_vida(desconto)` = vida mediana, medida nas próprias fotos, das ofertas com desconto parecido. Aviso: o que sobrevive até a foto seguinte é o que ninguém quis (seleção adversa); o relatório do backtest mostra as duas variantes.

**Venda.** Lote hipotético de n unidades a preço p, postado em `t_k + δ_react`. Em cada intervalo seguinte j, as unidades de terceiros que venderam com prioridade pior que a nossa teriam sido as nossas:

```
preenchimento_j = min( n restante ,  (1 − π_react) · S_j(pior que p) )
S_j(pior que p) = vendas inferidas no intervalo j a preço > p  (e a preço = p atrás de nós, conforme Ω)
```

Usa `S_lo` sem a correção ξ (conservador) e, em paralelo, com ξ (central). A cobertura feita por terceiros já está nos dados: se a fronteira nunca chega a p, o lote não vende. O que os dados não têm é a reação dos concorrentes à nossa presença; `π_react` é o desconto por isso. Depósito, corte, expiração em D e as decisões de cancelar e repostar entram com os mesmos parâmetros e com custo de clique.

**Lance.** Não dá para testar com fotos: não se sabe quem mais daria lance. Só o diário de lances próprios avalia esse sinal.

**Impacto.** Vale para lote `≤ s_cap·λ·Δ` por intervalo. Acima disso (reset), o backtest marca "impacto não modelado" e o resultado é só um teto.

### 10.3 Vieses

| Viés | Como aparece | Controle |
|---|---|---|
| Olhar para o futuro | V, λ, fatores sazonais, priores de categoria ou parâmetros calibrados com dados posteriores à decisão | validação progressiva: calibra em `[0, T_1]`, testa em `(T_1, T_1 + T_t]`, avança; parâmetros congelados no teste |
| Uso da foto seguinte | a inferência de venda usa `t_{k+1}` | permitido para preencher, proibido para decidir em `t_k` |
| Sobrevivência de itens | só entram itens que ficaram na lista porque deram certo | incluir todo item que algum dia foi varrido, inclusive os que saíram |
| Sobrevivência de fotos | só há fotos nas horas em que o dono jogou | métricas por hora de sessão; não extrapolar para horas sem foto |
| Seleção adversa na compra | pechincha que durou é pechincha ruim | variantes com e sem preenchimento; `τ_vida` |
| Múltiplos testes | limiares ajustados nos mesmos dados | registrar quantas configurações foram testadas; decidir pelo teste fora da amostra; comparar com a linha de base aleatória |
| Reflexividade | nossa ação muda a escada | teto de lote; `π_react` |
| Fim da amostra | estoque aberto marcado a custo ou a V | marcar a `W*_lcb` |
| Vendas subcontadas | `S_lo` é limite inferior | reportar as versões conservadora e central |
| Cadência fixa | o backtest só vê os instantes gravados; não avalia outro agendamento de consultas | declarar a limitação |

### 10.4 Métricas

```
Lucro líquido    Π = Σ vendas·(1−c) − Σ compras − depósitos perdidos + (marcação final − marcação inicial do estoque)
Lucro por hora     = Π / horas de sessão ativa
Lucro por clique   = Π / (compras + postagens + cancelamentos + lances + coletas)
Giro               = custo das unidades vendidas / estoque médio a custo, por dia ;  dias de estoque = 1/giro
Taxa de acerto     = lotes fechados com lucro / lotes fechados ;  fator de lucro = Σ ganhos / Σ perdas
Drawdown máximo    = max_t ( pico de B até t − B(t) ) / pico ;  tempo submerso
Lucro por estratégia: cada lote carrega a etiqueta do sinal que o originou (custo por PEPS dentro do item)
Retorno do capital = Π / (capital médio empregado · dias) ;  média do PnL diário / desvio do PnL diário
Calibração: Brier de P(venda), cobertura do IC de V, desvio de Poisson de λ, η_real por estratégia
```

Incerteza das métricas: reamostragem em blocos de um dia (`N_boot` réplicas). Linhas de base: não fazer nada; entrada aleatória com os mesmos tetos; regra ingênua (cobrir sempre por um tick, duração máxima).

**Modo sombra** (no jogo): o motor grava recomendação e preenchimento hipotético sem o dono agir. É o único teste sem risco de olhar o futuro e mede também a taxa "já tinha sumido".

### 10.5 Pseudocódigo

```
função backtest(fotos, params, T_ini, T_fim):
  estado ← vazio ; carteira ← {ouro = B0, lotes = {}}
  para cada foto f em ordem de tempo, T_ini ≤ f.t ≤ T_fim:
      d ← diferenca(foto anterior do item, f)
      preenche_vendas(carteira, f.item, d)            -- regra de 10.2, antes de atualizar o estado
      expira_e_devolve(carteira, f.t)
      atualiza estado do item com f e d                -- seções 1, 2, 8, 9
      para cada recomendação r de motor(estado, carteira, f):   -- seções 4 a 7
          agenda(r, f.t + δ_react)
      executa agendadas vencidas contra a foto corrente
  marca estoque final a W*_lcb ; devolve métricas e a lista de lotes
```

### 10.6 Hipóteses, modos de falha e dados

- Hipóteses: demanda não muda com a nossa presença (lote pequeno); as fotos gravadas são completas e têm relógio confiável.
- Falhas: backtest lucrativo só por preenchimento otimista de pechincha; calibração e teste na mesma semana de um servidor em formação (regime muda); parâmetros de jogo errados (corte, depósito) invalidam tudo, por isso entram medidos.
- Dados que precisam existir para o backtest: escada compacta de cada foto (não só os resumos), diário de ações do dono com hora, estado dos leilões próprios a cada foto, e o conjunto de parâmetros vigente em cada sessão.

## 11. Orçamento computacional

### 11.1 Fatia por quadro

Fatia `T_q` de CPU por quadro para o motor (a 60 quadros por segundo o quadro inteiro tem 16,7 ms). Estimativa de ordem de grandeza para o interpretador Lua 5.1 sem JIT: 1.000 a 3.000 iterações de laço simples com acesso a tabela por milissegundo. É inferencia; medir no cliente com o relógio de alta resolução (Incógnitas) antes de fixar `T_q`.

### 11.2 O que roda onde

| Cálculo | Custo | Onde |
|---|---|---|
| Preço robusto de uma escada (J degraus) | O(J); 300 degraus ≈ 0,2 a 0,5 ms | jogo, uma escada por quadro |
| Diferença de duas escadas (fusão de listas ordenadas) | O(J0 + J1) | jogo |
| EWMA, Gama-Poisson, CUSUM, fatores sazonais | O(1) por foto ou por bloco | jogo |
| P(venda) pela tabela (16 leituras e 2 logaritmos) ou Erlang (laço ≤ 200) | 20 a 50 µs por chamada | jogo |
| Melhor postagem de um item: `(2·K_lvl + 4)·|𝒟|` candidatos, 3 lotes, 6 chamadas de P cada | cerca de 1.500 chamadas: 30 a 75 ms | jogo, fatiado em 15 a 40 quadros; avaliar tamanhos de lote só nos 3 melhores candidatos corta dois terços |
| Sinais de compra de um item (k até `K_flip`) | `K_flip` vezes a melhor postagem; reaproveitar P entre k | jogo, fatiado, só para itens com gatilho |
| Custo recursivo de conversão | memoizado; recalcula só o que ficou sujo | jogo, fatiado |
| Reset (`K_reset` degraus, fórmulas fechadas) | O(`K_reset`) | jogo |
| Mediana e MAD de um anel de 64 | duas ordenações de 64 | jogo, sob demanda |
| Perfis de concorrentes | O(donos na escada) | jogo |
| Varredura completa, se existir (dezenas de milhares de linhas) | `N_fatia` linhas por quadro | jogo, fatiado ao longo de segundos |
| Tabela de P(venda) (simulação) | minutos, uma vez | mesa; embarcada como dado |
| ξ por subamostragem, recalibração de P, elasticidades, pesos de encolhimento, limiares de alarme | regressões e validação | mesa |
| Backtest, reamostragem, Monte Carlo de reset | minutos | mesa |
| Histórico bruto de escadas | compactação e arquivo fora das SavedVariables | mesa |

A mesa devolve um arquivo de parâmetros que o addon lê no reload seguinte (hipótese de projeto; o jogo só grava as SavedVariables no reload ou na saída, conforme P7).

### 11.3 Estruturas de dados

- **Anel (buffer circular)** por item: vetores paralelos de tamanho fixo `N_anel` e um índice de cabeça. Nenhuma tabela nova por foto: criar e largar tabelas gera lixo e pausas do coletor.
- **Estado O(1)** por item: `x̂_f`, `a`, `W2`, `t`; `x̂_T`; `SA`, `SB`, `SF`, `SN`; contadores de oferta; `g⁺`, `g⁻`; cerca de 30 números.
- **Resumo por dia**: anel de `N_dias` com mediana, mínimo, máximo, vendas inferidas, exposição, oferta nova, número de fotos, parcela censurada.
- **Sazonal**: 42 caixas com `S`, `E`, `ȳ`, `n` por categoria; por item só para os `N_foco` itens em foco.
- **Quantis em fluxo**: histograma de baldes logarítmicos. Balde `= piso( ln(p/p_ref) / ln(1 + g_h) ) + N_h/2`, com `N_h` baldes de largura relativa `g_h`. Quantil por soma acumulada; os contadores decaem e os histogramas de dias diferentes se somam. Alternativa sem memória: algoritmo P² (5 marcadores por quantil), que não se soma entre dias.
- **Escada compacta** para o diário bruto: `K_lvl` degraus exatos mais a cauda em baldes geométricos, gravada como texto com diferenças; a mesa drena a cada reload.
- **Coortes** por degrau para a expiração em commodity: lista limitada a `N_coortes`.

### 11.4 Precisão numérica com preços em cobre

- Número do Lua 5.1 é ponto flutuante de 64 bits: inteiros exatos até 2^53 ≈ 9,0·10^15. Preço em cobre e quantidade cabem com folga; o produto preço × quantidade é exato enquanto ficar abaixo disso (10^9 cobre × 10^6 unidades = 10^15).
- Somas longas de `p·q` (semanas) não devem ser acumuladas em cobre: guardar média incremental ou acumular em prata.
- Estatística sempre em `ln p`; converter de volta e arredondar ao tick: `p = piso(exp(x)/tick + 0,5)·tick`.
- Comparar preços como inteiros; nunca usar número fracionário como chave de tabela; fila e quantidade são inteiros.
- Probabilidades perto de 0 e 1: limitar a [0,001; 0,999] antes do logit; o termo exponencial da gaussiana inversa em log (seção 3).
- Tamanho: cada número em vetor ocupa 16 bytes. Anel de 64 fotos × 10 números ≈ 10 KB por item; 500 itens ≈ 5 MB em memória e cerca de 3 MB em texto nas SavedVariables. Escadas brutas: 40 degraus ≈ 640 bytes em texto; 500 itens × 20 fotos ≈ 6 MB, por isso a drenagem na mesa.

### 11.5 Agendador de consultas sob throttle

```
prioridade_i = peso_i · (1 − exp(−idade_i / Δ_alvo(i)))
peso_i       = capital exposto no item + EV médio por hora dos sinais do item + bônus se há leilão próprio ativo
gatilho      : se a consulta resumida mostra preço mínimo ou quantidade total mudando mais que θ_gat, a idade conta em dobro
capacidade   : N_foco ≤ c_q · média(Δ_alvo)          (c_q = consultas por minuto que o throttle sustenta)
```

A cada vaga do throttle, consulta o item de maior prioridade (varredura linear de algumas centenas de itens por segundo: trivial).

### 11.6 Esboço do fatiamento

Nomes de API são pista do retail; a disponibilidade de corrotinas e do relógio no Forever está em Incógnitas (a alternativa é máquina de estados explícita).

```lua
local function tarefa_escada(t0, L)
  for j = 1, #L.p do
    -- processa o degrau j
    if j % 64 == 0 and relogio_ms() - t0 > T_q then t0 = coroutine.yield() end
  end
end
-- a cada quadro: retoma tarefas da fila até gastar T_q
local function ao_quadro()
  local t0 = relogio_ms()
  while fila[1] and relogio_ms() - t0 < T_q do
    coroutine.resume(fila[1], t0)
    if coroutine.status(fila[1]) == "dead" then table.remove(fila, 1) end
  end
end
```

Modos de falha: tarefa que nunca cede (laço sem ponto de cessão) trava o quadro; fila que cresce mais rápido do que esvazia (medir o atraso e descartar tarefas de itens de baixa prioridade); SavedVariables grande demais alonga o reload (teto de tamanho e drenagem).

## Afirmações que mais pesam

Se uma delas estiver errada, o motor quebra. Todas têm marca inferencia.

| Id | Afirmação | Derivação |
|---|---|---|
| QNT-01 | Com prioridade de preço, toda venda entre duas fotos ocorre a preço ≤ F (o degrau mais barato com sobrevivente); sumiço acima de F é cancelamento ou expiração. | 2.1 |
| QNT-02 | A venda inferida é limite inferior e o viés cresce com o intervalo: no sintético de 30 un/h recupera 83% a 5 min e 40% a 60 min. Daí a correção ξ e a cadência `Δ ≤ 0,4·l_f/λ`. | 2.2, 0.3 |
| QNT-03 | Valor justo = média aparada das `λ·H_ref` unidades mais baratas depois do filtro de isca, combinada por precisão com o preço das vendas inferidas; a variância soma erro de medida e idade. | 1.2 |
| QNT-04 | Vender é primeira passagem de uma fila com deriva `λ_p − ν_f`; em regime estacionário `ν ≥ λ`, então a posição na frente é passageira; com `ν_f > λ_p` a chance de vender decai exponencialmente com a fila. | 3.1, 3.2 |
| QNT-05 | As fórmulas fechadas erram até 0,27 com lotes grandes; o modelo exato depende de 4 números e cabe numa tabela de cerca de 6 mil entradas calculada fora do jogo. | 3.2 (f), 0.3 |
| QNT-06 | Contra concorrente que cobre com tempo médio `τ_r`, a chance de vender por ciclo é `(λ·τ_r/(1+λ·τ_r))^(q+1)`. | 3.2 (e), 9.3 |
| QNT-07 | Valor de liquidação `W(p, D)` (4.1): preço líquido menos depósitos perdidos, cliques e custo de carregar, divididos por P; o ótimo está num conjunto finito de candidatos e não depende do custo de aquisição. | 4.1, 4.2 |
| QNT-08 | Cancelar e repostar se e só se `Δ_canc > m_hist` (4.6). | 4.6 |
| QNT-09 | Todo sinal de compra é o mesmo teste: valor de saída conservador na escada pós-compra contra o custo; a fração do sniper é derivada por item. | 5.1, 5.2 |
| QNT-10 | Reset fecha só se `λ_R/ν_R > f*` e `Q ≤ H_R·(λ_R/f* − ν_R)`; em item líquido o modelo pessimista dá valor esperado negativo. | 6.3 |
| QNT-11 | Kelly com incerteza `f = k_K·μ_r/(σ_r² + σ_V²)`; a chance de a banca cair à fração x é `x^(2/k_K − 1)`. | 7.2 |
| QNT-12 | Com poucos dados, a sazonalidade vem do encolhimento Gama-Poisson para a categoria, e a quebra de regime se detecta pela amplitude na categoria. | 8.1, 8.2 |
| QNT-13 | No backtest, um lote hipotético a p é preenchido só pelas vendas inferidas com prioridade pior que p, e os parâmetros usam só o passado. | 10.2, 10.3 |
| QNT-14 | Tudo que roda no jogo tem estado O(1) por item e custo O(J) por foto; preço em cobre é exato em ponto flutuante até 2^53. | 11.2, 11.4 |
